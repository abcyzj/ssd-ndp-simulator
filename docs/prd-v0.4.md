# SSD 近存计算仿真平台 V0.4 产品需求描述

版本：0.4  
日期：2026-11-03（Asia/Shanghai）  
主题：真实图搜索插桩、静态 IR 采集与依赖驱动仿真、CPU Cost Model 与 Validator
状态：正式需求基线，待实施。本文的阶段、接口和验收均为需求，不表示相关能力已经实现或精度已经达标；当前可运行交付仍为 [V0.3](releases/v0.3.md)。

## 1. 产品目标

V0.4 在现有 SIFT1M 图搜索和仿真后端上，建立“独立原生程序执行真实图搜索 → 插桩采集静态 IR → 静态 IR 输入仿真器”的流程，并完成 CPU 成本建模、模拟对拍和盘控下沉实验。新路径的搜索操作及依赖在采集时冻结，仿真时按依赖与资源重新计算执行时间。

**首要交付目标：在当前 Mac 上，使内存驻留、单线程、非下沉图搜索的模拟结果、工作量、CPU 服务需求、查询延迟和 QPS 与独立原生程序实测相符，并提供可追溯的验收证据。** 在此基础上，使用现有 SSD 模型比较 Host 与 Controller 两种 L2 放置，分析给定硬件参数下的时间和资源变化。

使用者为存储架构研究者、负载与算子开发者。使用者应能区分搜索语义是否正确、CPU 成本是否可信，以及 SSD/盘控性能是否经过实机验证，避免仅凭 QPS 接近就推断下沉收益可信。

本版先验证 CPU。真实 SSD 端到端校准、真实盘控硬件校准以及多线程严格精度达标不作为本版交付承诺。

本方案适用于当前只读、确定性的 `ndpsim-ranked-expansion-v1`：在数据、图、查询、算法、数值和搜索参数固定时，每查询的搜索路径不由服务延迟决定。静态 IR 因而可用于相同逻辑负载的成本、资源与 L2 放置比较；它不支持由竞速、超时、取消或近似数值改变搜索分支的反事实实验。

## 2. 需求依据与文档权威

- 设计来源为《SSD 近存计算仿真平台：Profiler、Cost Model 与 Validator PRD（V0.1）》及本轮已确认方案。该来源原以 DiskANN 为目标；本版已将所需约束完整归入本文，不依赖外部文件才能实施。
- [V0.3 PRD](prd-v0.3.md)、[IR 规范](ir-v0.3.md)和[交付记录](releases/v0.3.md)定义继承基线。V0.3 已完成动态 IR 和真实结果闭环，不将其重新降为未来能力。
- [搜索语义](search.md)、[契约](contracts.md)、[盘控资源](controller.md)、[输出口径](output.md)与[模型限制](model-limitations.md)继续约束继承路径。
- [SIFT1M 实验](sift1m.md)、[现行测试](testing.md)和[扩展接口](extensions.md)是输入、回归与实现核查入口。

V0.3 的行为迁移要求不校准硬件参数；V0.4 明确增加**显式启用的 CPU 校准路径**，并增加独立的内存驻留数据提供方式。该增量不追溯修改 V0.3 结论，不自动改变原配置、成本参数或默认数据路径。后续实现应将新增接口、计费边界和测试同步到相应现行文档。

**本次需求修订明确取代此前 V0.4“全程动态生成 IR、Trace 只作核对、不实现文件回放”的决定。** 新增静态 IR 采集和执行为本版正式交付路径；V0.3 的动态 `ir` 和冻结 `direct` 保留为兼容与独立对照。V0.3 PRD/IR 规范中禁止完整 Trace 驱动的要求继续约束旧路径，新静态路径按本文 §6.4 的契约执行。现有诊断日志、`ndpsim-ir/1` 和执行入口尚不具备该能力，不能仅改名后宣称可回放。

## 3. 当前基础与已确认决策

### 3.1 现有能力与缺口

| 环节 | V0.3 已有基础 | V0.4 所需增量 |
| --- | --- | --- |
| 算法 | `ndpsim-ranked-expansion-v1`、真实 FP64 L2、稳定批次与搜索闭环 | 共享纯算法函数和独立原生程序 |
| 算子测量 | 距离与 candidates 的本机粗测工具 | 完整查询、互斥 CPU 计时桶、采样和扰动测量 |
| CPU 模型 | Distance/Control、setup/rate、FIFO/slots | 按算子及工作量选择可替换 CPU Profile |
| 执行输入 | 动态类型化 IR、真实可见值、依赖与生命周期 | 原生插桩采集、版本化静态 IR 包、依赖驱动执行入口及内存驻留配置 |
| 对照验证 | direct/ir、host/controller 的独立核对 | 原生实测与模拟的分层精度验证 |
| 下沉 | L2 本地读取、缓冲、计算与真实结果返回 | 使用新 Host 成本进行条件预测与敏感性分析 |

现有粗测只是固定输入、缓存热场景下的功能实现诊断，不是完整算法基准或 CPU Profile。历史构建、定向测试和 V0.3 完整验收均不能作为 V0.4 已完成的证据。

### 3.2 已确认的产品决策

| 项目 | 本版决定 |
| --- | --- |
| 首个实测平台 | 当前 Mac，macOS / arm64；记录实际 CPU、系统、内存和构建身份 |
| 正式负载 | 现有 SIFT1M、锁定 NSG 图和 `ndpsim-ranked-expansion-v1` |
| 严格精度出口 | 内存驻留、单线程 Host 算法 |
| 多线程范围 | 2/4 worker 曲线与偏差诊断，不设首版严格精度出口 |
| 模拟执行方式 | 真实原生搜索采集完整静态 IR，仿真器按依赖和资源执行；采集时戳不驱动调度 |
| 功能值与路径核验 | 采集结果作期望证据；受信算子重算真实值与 Work，失配即停止，不在仿真中改写已采集路径 |
| CPU 调度 | 复用并按需扩展现有资源队列，不建立第二套事件引擎 |
| 存储与链路 | 复用现有 MQSim；不引入 SimpleSSD 或额外存储延迟模型 |
| 下沉范围 | 主机控制搜索，仅现有 L2 评分可放置于 Controller |
| 兼容策略 | 保留 direct 与动态 ir、既有默认成本；静态执行、新 Profile 和内存驻留配置均显式启用 |

## 4. 范围、算法与非目标

### 4.1 必须交付的能力

1. 不依赖 SST/MQSim 构建和运行的独立原生图搜索程序。
2. 基准、采样 Profile、完整静态 IR 采集三种模式，以及无插桩对照；详细诊断可按查询子集开启。
3. 与 IR 分离的 CPU 测量数据集、拟合流程和可替换成本 Profile。
4. 版本化静态 IR 包、校验器和执行入口，在现有 SST 时间、Runtime 可见性与资源机制内支持内存驻留及 SSD 两条映射。
5. 算子、查询、批次吞吐三层 Validator，自动生成精度与失败诊断报告。
6. 相同 SSD 数据路径下 Host/Controller 的 L2 下沉对照与参数敏感性报告。
7. 输入、源码、构建、硬件、模型和产物身份记录，持续测试及继承回归。

### 4.2 算法与数值约束

保持既有固定入口、全体已评分集合、前 L 候选、B 个扩展、E 扩展预算、chunk 分块、邻居升序去重及最终全体已评分 top-k。保留 scored/expanded 的更新时点、检查/比较计数，以及整批邻接与整批评分的汇合语义。

输入仍为 FP32，平方 L2 使用固定维序 FP64 减/乘/加，禁用 fast-math/FMA 改写，同分按 uint32 ID 决定。算法不是 DiskANN，也不因图来自 NSG 就改称忠实 NSG 搜索。不得在本版中更换 heap/hash、优化排序或精度、重建更优图来掩盖校准差异。

纯函数可以共享，但保留独立数值、搜索和账本核对器，不能仅由两个共用实现相互证明正确。

### 4.3 明确不做

- 完整 DiskANN、PQ、第二类负载、Deep10M、新数据集或新计算位置。
- 按采集时戳或逐次实测耗时推进的开环请求回放、任意日志直接执行、任意程序/DAG 的通用回放器或断点恢复。
- 脱离已采集数据/算法身份复用搜索路径，或将预计算距离、选择结果作为免除真实服务与功能核验的执行值。
- CPU 指令级/周期精确模型，精细 Cache、NUMA、DVFS、OS 抢占或内存带宽竞争模型。
- 原生程序的异步 SSD 搜索实现、真实 SSD 端到端校准或盘控硬件实测。
- 自动算子融合、自动 placement 搜索、多 SSD、多主机、可写索引或 SSD 自主图搜索。
- 将单机 Profile 泛化为任意硬件成本，或承诺 Controller 必然更快。

## 5. 用户流程与数据分层

```text
相同数据 / 图 / 查询身份 / 搜索参数
    └─ 独立原生程序（真实执行搜索）
         ├─ 无插桩 / 基准模式 → 实测查询结果、CPU 统计、QPS 与延迟
         ├─ 采样模式         → 算子工作量与 CPU 时间样本 → CPU Profile
         └─ 完整 IR 采集模式  → 静态 IR 包（操作、逻辑访问、依赖、期望摘要）
                                   ↓ 身份 / 完整性 / 语义校验
                              静态 IR 执行入口
                                   ├─ 内存驻留 Host + CPU Profile → CPU 模拟对拍
                                   └─ SSD + Host/Controller → 条件预测与下沉对照

原生实测 / 静态 IR / CPU Profile / 模拟产物 / direct与动态ir参考 → Validator
```

使用者先核对输入和构建身份，完成训练采集与模型冻结，再采集评价侧 IR、运行独立评价及下沉实验。完整静态 IR 是新路径必需的执行输入，须覆盖本次全部查询；不要求每次无插桩基准重复采集。性能基准、CPU 采样、IR 采集分别运行，IR 采集运行的墙钟不能替代低干扰基准。detail8 只限制额外诊断，不限制静态 IR 的查询覆盖。

以下数据必须分离保存：

| 数据层 | 内容与用途 | 禁止行为 |
| --- | --- | --- |
| 静态语义 IR | 完整操作、对象引用、依赖、批次、逻辑访问、工作量和期望结果摘要；作为执行输入 | 将实测时戳/耗时作为调度依据，或以预知地址/结果跳过依赖、读取与计算 |
| 诊断 Trace | 选定查询的详细状态、IR 到资源关联及核对证据 | 将不完整日志当作完整可执行 IR 包 |
| Measurement Dataset | CPU 时间、墙钟时戳、计时开销、采样条件和质量 | 把阻塞等待当 CPU 服务需求 |
| CPU Profile | 模型、系数/表、训练范围、硬件和构建身份、误差 | 在 IR 中固化硬件相关时间，或仅以 QPS 拟合 |
| Simulation Config | 数据驻留、CPU 配额、模型选择、placement 与硬件参数 | 隐式切换数据位置、成本或资源数量 |

## 6. 功能需求

### 6.1 独立原生程序

| ID | 要求 |
| --- | --- |
| FR-04-N01 | 提取现有距离、候选合并、前沿选择和邻居去重的纯函数，供原生程序与 IR 适配层共用；direct 保留为冻结参考。 |
| FR-04-N02 | 原生程序直接执行算法，不调用 Runtime、HostCpu 模拟服务或事件引擎，不读取模拟时间；根 CMake 提供仅构建原生程序的选项，不准备或链接 SST/MQSim。 |
| FR-04-N03 | 测量前加载并触碰完整 base、图和查询，完成身份检查与预热；查询阶段执行真实的按 ID 内存访问，不预生成完整访问序列。数据加载、校验和落盘位于测量窗口外。 |
| FR-04-N04 | 支持单线程及 2/4 worker；每个 worker 串行执行分配到的查询，共享只读输入，保持每查询状态隔离。输出 top-k、距离、Recall、扩展与评分统计、CPU 时间、时延、批次 QPS 和退出状态。 |

内存驻留指算法访问主机内存，不保证整个数据集位于 CPU cache，也不承诺 OS 永不换页。须记录驻留准备方法、内存压力及测量期缺页信息；异常分页影响运行条件时标记样本不适用。

### 6.2 Profiler

| ID | 要求 |
| --- | --- |
| FR-04-P01 | 提供无插桩对照、低干扰基准、采样 Profile、完整静态 IR 采集；详细诊断可选。采集来自同一原生程序真实执行，不由模拟器或手工脚本预生成搜索序列；模式间算法、数值、输入身份和搜索参数一致。 |
| FR-04-P02 | 查询和批次使用单调墙钟；同步 CPU 区间使用 `CLOCK_THREAD_CPUTIME_ID` 或等价线程 CPU 时钟，记录时钟来源、单位和分辨率。跨线程工作按 query/task/worker 关联。 |
| FR-04-P03 | CPU 时间采用互斥桶或 exclusive-time 归因；覆盖内存取数与准备、L2、合并、选择、去重及必要状态维护，明确解码、复制、分配和释放的归属。 |
| FR-04-P04 | 短算子采用抽样或批量测量，单列计时开销、原始与修正时间、低质量样本和未归因 CPU 比例；不产生伪造的负服务时间，不用 `wall − I/O` 或端到端残差训练控制成本。 |
| FR-04-P05 | 在真实读取、评分、合并、选择、去重、状态转换和终止边界插桩，输出 §6.4 的完整静态 IR。记录原始查询身份、轮次、语义批次、算子/阶段、逻辑对象与字节、ADDRESS/DATA/CONTROL/ORDER 依赖、Work 及期望结果摘要；可与 direct/动态 ir 按稳定语义键关联。 |
| FR-04-P06 | 使用线程本地有界缓冲和批量输出，热路径不逐条同步写日志；CPU 测量可采样，执行所需 IR 操作与依赖必须全量、不抽样。设置输出预算与超时，报告丢失/截断；写入临时包，完成计数/hash/终态核验后才封包，未完成或缺事件的包不可执行。 |
| FR-04-P07 | 无插桩与低干扰基准执行至少三组 A/B/A；记录顺序、全部样本、波动和 QPS 扰动。Profile/Trace 模式另报开销，不要求它们满足低干扰门槛。 |

CPU 计时桶的最小语义覆盖如下；桶名与 IR 算子不是必须一一对应，实际边界须在采集前版本化：

| 语义阶段 | 主要特征 | 计费规则 |
| --- | --- | --- |
| 内存取数与准备 | 对象数、有效字节、分块、解码/复制量 | 与 L2 或控制桶互斥；不得既包含加载又另收费 |
| L2 | 向量数、维度、FLOP、输入/输出字节 | 对应 SCORE_L2 的 CPU 子阶段，不含 SSD/PCIe 等待 |
| MERGE_CANDIDATES | 旧/新评分数、checks/comparisons、字节 | 保留全体得分和现有合并语义 |
| SELECT_FRONTIER | L/B/E、候选检查数、expanded 规模 | 空选择仍保留原控制工作 |
| DEDUP_NEIGHBORS | 边数、scored 规模、checks/comparisons | 保留逐边检查、线性比较和有序插入 |
| 其他必要控制 | 状态更新、查询初始化/结束及明确的对象管理量 | 只承接其他桶未包含的真实工作，须独立测量 |

仿真器特有的 JSON、IR 校验、引用管理和诊断成本属于仿真效率开销，不作为目标原生程序的 CPU 需求。

### 6.3 CPU Cost Model

概念接口为 `estimate(operator, stage, work, hardware_profile) → service_ns + applicability`。这是拟议能力边界，不是已经存在的 API；实际语言接口和机器 schema 在实施时与测试共同冻结。

| ID | 要求 |
| --- | --- |
| FR-04-C01 | 按算子/阶段提供独立估计，支持常数、多变量线性和分段查表三类模型；相同语义工作可显式切换不同 CPU Profile。 |
| FR-04-C02 | 训练目标为独立测得的 CPU 服务时间；系数、表项和固定开销来自训练样本，不以查询 QPS、墙钟残差或评价集反向调整。 |
| FR-04-C03 | Profile 保存版本、硬件/系统/构建身份、训练数据来源、特征与单位、适用范围、样本数、误差和选择规则；输出可复现的拟合报告。 |
| FR-04-C04 | 输出有限、非负且不溢出的服务时间，舍入规则版本化。未知算子、缺模型、身份不兼容或训练范围外必须明确诊断；正式验证失败关闭，不静默回退到旧 rate 或外推。 |
| FR-04-C05 | 报告 MAE、相对误差分位数、分桶误差与残差趋势；接近计时分辨率的短算子另报绝对误差和样本质量，不以不稳定 MAPE 误导模型选择。 |

单机实测 Profile 只适用于其记录的构建、输入形状和运行条件。CPU cache/调度差异可作为限制与诊断，不通过加入任意补偿延迟隐藏。

### 6.4 静态 IR 输入、依赖执行与资源调度

| ID | 要求 |
| --- | --- |
| FR-04-S01 | 增加显式内存驻留数据提供配置，保持对象身份、逻辑访问、实际功能值和输入边界校验；这与现有 `content_backend=memory` 的功能内容存放方式不同。 |
| FR-04-S02 | 内存驻留路径不提交 SSD 请求，不通过把 MQSim 延迟设为零实现；内存访问、准备和 CPU 计算按互斥边界计费。 |
| FR-04-S03 | 新增显式静态 IR 执行入口，读取已校验的包，复用现有 IR 执行/映射、Runtime、HostCpu 和 EventBridge；只有 SST 推进时间。静态拓扑规定已采集路径，本次依赖、真实功能核验、资源服务和必要返回共同门控后继，不能按采集顺序或时戳发射请求。 |
| FR-04-S04 | 限制同时运行的 CPU 任务数并记录 busy、dependency wait、queue wait；明确区分 worker 数、查询并发和 CPU slots，不将 `max_inflight` 当作核数。 |
| FR-04-S05 | 校准配置遵循原生 worker 的每查询执行顺序，不因空闲 CPU slots 而额外并行执行原生程序中串行的评分分块；跨查询仍可按 worker/资源配额并发。 |
| FR-04-S06 | 保留所有权、异步 continuation、失败传播及最终排空规则；用流式包校验、查询索引及有界执行窗口，不常驻完整历史 DAG。已知未来操作不授予读取、预取、预占 credit 或结果权限；保留仍有消费者的值，最后使用且回调排空后回收。 |
| FR-04-S07 | 提供独立于旧诊断格式的版本化可执行包 schema、采集器和校验器，满足下列完整性与依赖规则；未知版本、缺查询/终态、非法引用、环、错状态版本、内容/Work/决策失配均失败关闭。 |
| FR-04-S08 | 对同一包重新估计成本并执行资源调度；明确可复用参数和必须重新采集的变化。不得静默重建搜索分支、回退动态模式或将采集时延作为缺模型的补值。 |

复用现有非抢占 FIFO/slots 抽象，不承诺精确模拟 OS 抢占和异构核分配。新的 CPU 计费边界只在显式 Profile 路径生效，不以本版采样结果改写旧配置。

#### 6.4.1 静态 IR 包的最小契约

包由 manifest、逻辑对象目录、每查询操作流/索引、完整性尾记录及期望摘要组成，可引用经 hash 校验的外部 base/图/query 文件，不复制全部向量或每轮完整状态快照。包 schema 与产品版本、旧 `ndpsim-ir/1`、Measurement、CPU Profile 分别版本化；具体字段和配置名实施时冻结。

采集的期望计数/结果存于独立核验字段，不作为旧IR提交的受信实际Work；不能放宽现有“实际计数由evaluate产生”的校验来接入静态包。包内query局部ID须映射到本次执行的全局ID，不复用已回收的Runtime ID。

| 内容 | 必须表达的语义 |
| --- | --- |
| 来源与适用性 | 原生采集器/算法/数值/构建身份，数据/图/查询 hash、原始 query ID 与顺序，entry/k/L/B/E/语义 chunk，算子与包版本，采集完整性与适用条件 |
| 对象与访问 | 逻辑对象/记录 ID、内容版本、shape、有效字节与批次内顺序；LBA、sector/NAND/PCIe 字节由运行时映射产生，不固化原生指针或物理布局 |
| 操作与引用 | 查询、轮次、批次、算子/阶段、类型化输入输出、状态版本与转换；查询内单调 ID 和只引用前序 producer 的拓扑序，空批次、初始化和终止也完整记录 |
| 依赖 | ADDRESS/DATA/CONTROL/ORDER、生产者端口、语义批次 JOIN；通过可见输出引用地址，不用已知 ID literal 绕过选择/去重依赖；仅入口和合法固定参数可直接给定 |
| 工作量与核验 | 真实执行采集的有序评分/扩展 ID、Work、输出形状、决策及结果摘要，作为期望证据；每个操作可由真实输入重算并核对，不能直接信任采集计数用于收费 |
| 完整性 | 每查询操作/依赖数、终止原因、摘要、分片 hash 与包 hash；缺失、重复、截断、越界、非法前向引用/环或错误 query/scope 均拒绝 |

语义依赖与执行策略分开：不将多 worker 采集时的全局交错、墙钟顺序或无关查询之间的偶然顺序编码为依赖。A 组使用与原生一致的 worker 占有整查询及串行 chunk 规则；B/C 按现有 SSD 映射执行，允许其原有批内并行和盘控容量分块。各策略须版本化，不因静态文件排列而新增串行化或提前发射。

#### 6.4.2 执行、真实值与失败边界

静态执行器替代动态搜索前端的“生成下一批操作”职责，不替代受信功能算子、存储服务或可见性门控。读取后重算邻接、L2、合并、选择、去重和实际 Work；采集的期望值仅供验证，不作为 Runtime 预填输出。状态从合法初始化和已完成转换重建，禁止提前注入未来 scored/expanded 状态。算子功能结果保持私有，输入、目标服务与必要返回完成后才可见；继而核对期望输出、控制许可和下一操作地址，匹配后才允许后继实际提交。

若真实选择/去重/距离、Work、状态转换或终止与包不符，终止该运行并按既有安全边界排空，报告 query/批次/op/字段。不得继续沿原地址读取，不得临时补分支后仍称同包执行。首版不交付省略功能计算的 timing-only 模式。功能核验与文件解析的宿主墙钟不推进模拟时间，目标 CPU 需求仍由独立 Profile 估计。

#### 6.4.3 复用与重新采集

同一包可在逻辑语义不变时改变 CPU Profile、合法 slots/worker 配额、SSD/PCIe/Controller 参数、布局、驻留和 Host/Controller L2 映射，重新运行并生成独立配置/映射身份；每个组合仍须检查 Profile 适用性、容量、顺序策略与数值一致性。worker 变化只在查询私有状态、只读输入、无跨查询数据依赖且包未冻结全局分配时合法，查询领取和资源竞争由本次调度决定。

数据/图/query 内容或查询集合、entry/k/L/B/E/语义 chunk、算法、数值规则、容器/计数或影响语义的构建变化必须重新采集并核对。改变硬件引发超时/取消、竞速选分支、提前停止或数值变化不在本版静态预测范围；不能宣称旧包仍代表新程序搜索。旧包与新输入错配须启动前拒绝；合法内容扰动须重采得到新路径，再与 direct/动态 ir 独立核对。

#### 6.4.4 采集与评价的独立性

先在 tuning32 冻结采集 schema、CPU 桶、模型选择和 Profile，再对 evaluation128 采集完整 IR 与独立测量。评价侧 IR 的路径/Work 可作负载输入与核验证据，不得回流训练、修改特征/范围/系数或补成本。采集运行与无插桩/低干扰基准必须结果和工作量一致，记录各自开销；不能拿插桩延迟作为目标测量。静态 IR、CPU Profile 和模拟配置分别保存身份与 hash。

| --- | --- |

## 7. 时间、指标与实验身份

### 7.1 测量窗口

- 查询开始为实际接纳时刻，结束为最终 top-k 在 Host 可见；保留 offered、admission wait、latency、offered latency 和 drain end 的区别。
- 批次 QPS 为完成查询数除以首个查询接纳到最后一个结果可见的窗口。原生与模拟必须使用相同查询批次、请求供给方式和窗口定义；不得使用整个 SST 进程墙钟作为模拟 QPS。
- 主测试为固定有限批次，所有请求在测量起点可供接纳，按固定顺序由 worker/并发配额领取；不引入开放式到达模型，不称为稳态吞吐。
- 数据加载、哈希检查、预热、Profile 拟合、日志落盘和报告生成不进入查询窗口。窗口内实际发生的状态维护等 CPU 工作须归因，不能因不在 L2 函数内就忽略。
- 分位数沿用 nearest-rank，报告样本量。资源累计忙时不是端到端延迟，不能直接相加替代关键路径。

原生 worker CPU 时间和模拟 CPU 服务时间按一致边界对比。利用率按明确配额和同一时间窗口归一化；worker 忙碌率、进程 CPU 占用和物理 CPU 利用率分别命名，不相互替代。无法取得或控制的 CPU 频率、核绑定及计数器标为 Unsupported/未控制，不虚构固定策略。

### 7.2 身份与产物

沿用仓库 JSON/JSONL 产物习惯。每个实验的 manifest 至少记录：完整 Git commit、未提交 diff 和实际源码哈希、编译器/优化/数值选项、原生可执行文件与模拟库哈希、CPU/OS/内存及可得的频率/绑定条件、数据/图/真值/原始查询身份、搜索配置、worker/slots/并发、驻留策略、采样率/时钟、模型与 schema 版本、命令/退出码和产物 SHA256。静态执行另记采集运行/构建身份、包及分片 hash、查询覆盖、完整性校验结果、实际 execution engine/mode、映射/顺序策略及功能核验结果；采集身份与本次模拟身份分别记录。

SSD 实验另记录 MQSim fork、原生基线、相对原生 diff 与实际源码哈希、SST 完整 commit、布局/设备配置和初态。内容、LBA、驻留及各层字节保持分离，硬件来源按组件记录，不使用一个全局“已校准”覆盖所有资源。

交付产物至少包括原生基准结果、算子样本、全部所需查询的可执行静态 IR 包与校验报告、选定详细 Trace、CPU Profile/拟合报告、模拟结果与资源统计、A/B/A 扰动报告、精度报告、下沉敏感性报告及继承回归证据。大数据和运行产物继续保存在忽略的证据目录；不得靠复制完整数据到 Git 实现可复现。

## 8. 验证矩阵与验收标准

### 8.1 输入、切分与运行矩阵

V0.4 常规完整规模验收固定为 **14 个模拟配置**：静态执行的内存单线程四点4个、多worker诊断2个、旧默认direct/动态ir × Host/Controller兼容4个、静态执行的新Profile SSD Host参照1个与Controller算力扫描3个。逐项参数、配套采集/重复及深度回归条件见 [14配置验收矩阵](validation-matrix-v0.4.md)。这是配置数，不是总执行次数；原生至少三次、全查询 IR 采集、模拟确定性复跑、训练、A/B/A、detail8和定向/继承测试另计，不降低下述精度门槛。

V0.3完整52条保留为按需深度回归，不再每阶段或每次V0.4交付无条件重跑；旧默认行为变化、影响无法排除、跨配置异常或依赖/模型边界变化时按矩阵规范触发。触发而未通过时不得关闭兼容或总交付出口；未触发须记录影响依据。完整base四点CPU精度保留；旧默认完整base兼容收敛到主配置，其他交叉覆盖由定向测试承接，其覆盖范围不宣称等同原52条。

- 复用完整 1,000,000×128 SIFT1M base、锁定 NSG 图和[固定查询身份](../configs/benchmarks/v0.2-query-selection.json)。tuning32 用于样本采集、拟合及训练内模型选择；evaluation128 用于冻结后的独立评价。
- 正式单线程矩阵覆盖既有 L/E 四点：32/64、64/128、128/256、256/512；k=10、B=1、chunk=16，其余搜索与数值规则继承。按所有评价点逐项判定，不能只报告最接近的点。
- 每个性能点至少三次原生重复；模拟在相同输入/配置下核对确定性。2/4 worker 诊断采用固定 concurrency32、L/E=128/256；详细核对使用 detail8，并保留全评价集工作量/决策摘要。
- 小规模合成和真实 SIFT 子集用于定位问题，不能替代完整 base/固定评价集的正式出口。补充形状或训练样本须来自训练侧，记录用途；不得查看评价误差后重新拟合并仍称独立评价。
- 训练数据或范围不足时，相关评价点保持失败/不适用。修改 Profile 必须产生新版本，并清楚标明原评价已被用于诊断，不能掩盖验证集泄漏。
- 每个 L/E 点的静态包覆盖该点全部 evaluation128；多 worker 可按 §6.4.3 复用相同每查询 IR，B/C 复用主配置同一包。detail8 不是执行输入的覆盖上限。不同包重新采集、同包重复执行和不同映射分别记数。

### 8.2 验收矩阵

## 10. 兼容、资源与证据要求

- 常规验收采用14模拟配置及配套重复/采集、定向与完整继承测试；V0.3的52条为按需深度回归。新V0.4入口需独立计划/覆盖判定，不修改旧入口的52条完整性语义，缺项不能出成功。
- 日常旧配置默认仍为动态 `ir`、现有 SSD 数据路径和既有成本；V0.4 新验收 A/D/O 组显式选择静态执行及包路径。建议新增 engine `replay`（名称待实现冻结），不重定义旧 `ir`；新增 Profile、驻留、包 hash 与执行策略写入有效配置和 manifest。无效或不支持的组合拒绝，不静默改 engine/placement/驻留/模型。
- 原配置下 direct/ir 的模拟时序、请求、字节、资源和结果仍须严格等价；显式更换 CPU Profile 后时间变化属于模型变化，不应与旧默认配置混作等价对照。
- 沿用根 CMake、锁定 Python、SST 缓存和子模块维护规则；不修改 SST Core，不增加 MQSim 构建时 patch 栈，不自动提交、推送或初始化/升级依赖。
- 完整规模采集前重新冻结内存、磁盘、静态包/索引/验证临时文件及超时预算；旧预算未覆盖完整静态 IR，先 pilot 实测再确认。复用输入逐项验 hash，记录原生驻留副本和采集缓冲成本；不得把缩小 base/查询数或抽样 IR 后的通过当完整验收。
- 统计/详细模式分开，详细诊断只要求选定查询，但执行 IR 必须覆盖全部查询；资源、文件解析/校验和采集/日志开销单列。RSS 高水位、磁盘采样、定向 ASan等能力不升级为分阶段归因、硬隔离或完整泄漏审计。
- 失败运行与所有样本保留；重跑用新目录。静态核查、单测、小规模、完整 AC 与精度评价分别记录，未执行不标通过。

## 11. 风险与结论边界

| 风险 | 本版处理 |
| --- | --- |
| 极短算子计时和插桩改变执行 | 模式分离、抽样/批测、互斥计时、A/B/A、计时质量标记 |
| 纯函数共享掩盖共同错误 | 冻结 direct 参考与现有独立数值/搜索/账本核对器继续保留 |
| 静态路径不代表变化后的算法 | 冻结数据/算法/数值/搜索身份；语义变化重采，时序影响分支的程序标 Unsupported |
| 已知未来地址引入免费预取或提前服务 | 地址仍绑定 producer 的真实可见输出，依赖满足前不提交读/服务或占用 credit；延迟与失败探针验证 |
| 采集顺序固化偶然并发，或全量 IR 超预算 | 每查询语义 DAG 与执行策略分离；全量采集、流式校验和有界执行，重新测量包/索引及临时文件预算 |
| 原生、IR 状态维护边界不同 | 版本化 CPU 桶和映射，报告未归因比例，不加入任意补偿成本 |
| 内存驻留或多 worker 条件改变缓存/调度 | 记录环境、分页及波动；单线程严格验收，多线程诊断，不承诺跨硬件泛化 |
| 查询样本或形状超训练范围 | 冻结训练/评价切分与模型，超范围失败关闭，禁止静默外推 |
| QPS 误差抵消 | 逐层核对工作量、算子、CPU 服务与延迟；单项接近不能替代整体验收 |
| CPU 校准被误读为盘控真实性 | 按组件标注来源，只在相同 SSD 路径 B/C 间计算下沉收益，SSD/PCIe/Controller 保留未校准声明 |

V0.4 的完成标准是：**真实原生搜索产出完整、可校验的静态 IR，仿真器按依赖与资源执行并重算核验真实值，语义与工作量经 direct/动态 ir 及独立 oracle 核对；指定 Mac、构建、输入与运行条件下的单线程 CPU 模型通过独立精度验收；继承路径保持兼容；盘控下沉实验具有完整账本和明确的条件预测边界。**

即使 CPU 验证通过，SSD、PCIe 和 Controller 仍为 `configured_unvalidated`；不同数据准备方式下 Host CPU 成本的可迁移性也必须说明。固定评价128查询不等于全10k查询，P95 按本轮样本报告，p99 不作为稳定尾延迟结论；官方有限真值并列边界及既有 Unsupported 限制继续有效。
