## 运行入口

从仓库根目录构建；默认由根 CMake 准备锁定 SST，共享缓存可复用：

```sh
cmake -S . -B build/m3.4
cmake --build build/m3.4 -j4
python3 tools/run_pair.py --pair --config configs/archive/v0.1/m3.4/host.json --build build/m3.4 --output results/m3.4-pair
```

`--pair` 只生成一次数据与独立穷举真值，先运行 host，再让 controller 读取同一目录；写出两份有效配置、各自完整实验目录与 comparison.json。也可分别运行成对配置：

```sh
python3 tools/run_pair.py --config configs/archive/v0.1/m3.4/host.json --build build/m3.4 --output results/m3.4-host
python3 tools/run_pair.py --config configs/archive/v0.1/m3.4/controller.json --build build/m3.4 --data results/m3.4-host/data --output results/m3.4-controller
python3 tools/compare_placements.py results/m3.4-host results/m3.4-controller --output results/m3.4-comparison.json
```

两份配置仅 placement 不同，保留相同输入生成参数、搜索参数和主机控制成本，也同时记录两种资源配置。旧 M3.1 入口仍保持仅支持 host。完整验收入口为 `python3 tools/archive/v0.1/verify_m3_4.py`；日志、命令/退出码、输入及代码哈希、流量账本见 [证据索引](../../evidence/m3.4/README.md) 和 [manifest](../../evidence/m3.4/manifest.json)。

## 实现与数据路径

GraphSearch 增加异步评分能力注入；不向搜索暴露 ContentStore、MQSim 或研究账本。两种放置共用候选选择、邻接去重、已访问集合、候选合并和停止条件，仍由真实得分驱动后续访问。host 保持普通 NVMe 向量读取与 HostCpu 距离；controller 调用 M3.3 Open/Score/Close，使用正式本地存储、共享 PCIe、容量 credit、staging 与算术 slots。Controller 仍按配置 chunk 上限和容量推导确定性子块，GraphSearch 等完整语义批次的所有子块返回后才合并。容量改变子块数不会改变候选批次语义。

| 内容 | host | controller |
| --- | --- | --- |
| query | 主机 FP32，常驻本次查询 | 主机发起一次 QueryOpen，设备缓冲常驻至 CloseAck |
| 向量 | SSD → 普通 NVMe DMA → HostMemory → 主机距离 | SSD → LocalReads → DeviceBuffer → 盘控距离；不走主机向量 DMA |
| 邻接 | 普通 NVMe DMA 到主机，sector padding 及 SQ/CQ 均计费 | 与 host 相同，由主机控制扩展 |
| 评分命令 | 主机内部调用 | Score 封装计费，包含 header、dimension、chunk 和全部 uint32 IDs |
| 得分 | 主机运行时结果 | ScoreResult 包含 uint32 ID + FP64 distance，经实际返回到达后可见 |
| 候选、visited、expanded | 主机；HostCpu 明确控制成本 | 同左；无设备自主搜索 |

每查询从开始 Open（host 为直接评分）到最终 top-k 可见计 `latency_ns`；Close/CloseAck 是随后有计费的收尾，下一个查询等 CloseAck 后开始，实验总时间包括收尾。未把收尾隐藏成免费流量。参数仍为 configured_unvalidated，不以盘控更快为通过条件。

MQSim 独占 NAND/FTL/cache/CMT/PCIe；平台只计主机计算与独立新增盘控算术/缓冲。新增 LocalReads 只读观测回调输出实际 request、LBA、sector 和内部事务完成记录；不改变后端服务或算法可见信息。链路观察仅记录 enqueue/start/arrive、payload、wire 与原生服务时长，不重复计费。所有测量事件在确定性预装载排空后记录。

控制消息头、协议元数据与有效内容分层统计：QueryOpen 为 `64+4d`，Score 为 `64+4b`，ScoreResult 为 `56+12b`，OpenAck/Close/CloseAck 各为 48 B。普通邻接保留 NVMe 原生 doorbell/SQ/read-request/CQ 与实际 sector DMA 费用。wire 用原生 128 B TLP payload + 28 B packet overhead（READ_REQ 32 B），原生带宽为 4 lanes × 1 GB/s。此处没有另造 link 延迟公式替代 MQSim，验收只是独立复算现有观测值。

## 验收判定

独立 Python 对照器从原始 FP32 和图重新推导每轮候选、扩展和 top-k；不把访问 trace 提供给仿真。距离按 `abs 1e-9 + rel 1e-7` 判定，候选/扩展/排序后的 ID 必须完全相同。同分按 ID 决定。另核对实际 read 完成后才决策、ScoreResult 到达后才记录可见得分、邻接 ID/LBA 和候选扩展的因果关系。

流量逐项对账覆盖每个评分块的 ID 个数、实际向量 sector 集合、本地请求/事务、关联 task、得分字节、QueryOpen/ACK/Close、普通邻接/SQ/CQ/doorbell；每笔 link 必须恰有 enqueue/start/arrive，序列化时间符合原生公式，平台消息与真实 link 的 ID/方向/到达一致。controller 不得出现普通 vector read，全部普通 DMA 量必须等于邻接 sector 字节。credit reserve/release 独立重算且结束占用为零；Component 也检查 session、协议、slot、内容和 Runtime 结果全部回收。

实际矩阵与统计见证据索引。完整 CTest 50/50，ASan 隔离探针 13/13，验收脚本 10 组断言全部通过。默认 2048×32/32 查询共有 1289 条候选决策（含终止），两种放置 top-k/候选/扩展一致，Recall@10 均为 0.2875；各放置重跑事件完全相同。盘控向量 D2H=0、本地向量读取8922624 B，平台 payload/wire=444264/556096 B，普通邻接 DMA=643584 B，原生 NVMe wire=1081020 B。另覆盖无同分分支及单向量修改、B=2、容量限制 chunk=2 且实际语义批次大于2的多块返回、d=260 跨 NAND page、双算术 slots、同分 ID 排序，以及改坏距离/删去链路事件的负例。

## 限制

仍为单 rank/thread、单 SSD、顺序查询 `max_inflight=1`，不包含 M4.1 的有限查询并发、日志开关、完整 CSV/分位数或查询级 channel/die 关联。事件日志在本入口总是开启。默认生成图用于平台验证，不是完整 DiskANN 或高质量 ANN 索引；Recall 不必为 1。

新增缓冲独立于 MQSim DRAM，未建模二者共享竞争；无在途后端失败恢复、取消或重试。端点额外处理沿用 0 ns，参数未校准，结果不代表硬件绝对性能。ASan 仅覆盖隔离图/盘控/资源探针，不声称真实 SST 全流程或 MQSim 全面泄漏审计。本轮没有修改或重建独立原生 oracle 的源码，也没有更改 MQSim/SST；完整 CTest 运行既有普通路径回归，独立原生三组详细对照仍以 M3.3 证据为最近基线。本任务 AC-01/02/05/06 的端到端矩阵与后续完整并发/全 AC 回归应区别记录。
