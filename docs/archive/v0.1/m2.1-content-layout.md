## 内容和地址

`ContentStore` 构造时接管独立字节副本，此后只读。每个对象的 dataset/kind/uint32 ID/version、长度和 SHA256 均可查询；未知对象、错误版本、同一对象重复或冲突的版本/hash 均拒绝。不同对象当然可以具有相同版本。每次实验单一不可变快照，不提供原地修改/在线版本替换。SHA256 用空串、abc、百万 a 已知值及 Python hashlib 独立核对。

真实内容访问只授予可信句柄管理层，仓库公开接口没有任意数值读取或指针。`Handles::try_get` 返回范围字节的副本；`AlgorithmView` 仅开放 HostMemory try_get，没有角色选择、发布或 ContentStore 访问。可信执行器可分别访问 HostMemory/DeviceBuffer；SSDStorage 始终只作读依赖。应用不得持有可信 Handles 管理接口。

`Layout` 接收对象 byte offset 和 namespace sector **数量**，验证对象存在、版本、正长度、加乘溢出、对象字节重叠与 namespace 边界。不同对象可共用 sector，但不可覆盖相同有效字节。resolve 的半开范围先向外覆盖 512 B，再批内合并重叠/相邻 sector；每个 extent 保留逻辑对象范围及 extent 内偏移。大范围按当前普通 NVMe 65535-sector 请求上限拆分并裁剪 slices；NAND page 拆分仍由 MQSim 执行，没有在平台重复计费。

`ann_layout` 实现默认布局：vector stride=align_up(4d,512)，adjacency stride=align_up(4+4R,512)，先放连续向量区，再放独立邻接区，按 ID 递增，query 不映射到 SSD。返回两个 base、stride、end_lba 和完整 placements，可由后续实验输出记录。向量长度和邻接记录长度须符合声明尺寸；本任务不解析 FP32 或 degree/ID 数据格式，功能数值及数据集生成分别留给 M2.3/M3.1。

## 驻留与所有权

每个模拟副本独立调用 `Handles::create`，分配进程内从 1 单调递增、不复用的不透明 handle ID；每个所有权 token 也有稳定 ID。位置仅 SSDStorage、DeviceBuffer、HostMemory。初始 query 允许 HostMemory，vector/adjacency 允许 SSDStorage；模拟读目标仅 HostMemory/DeviceBuffer，始终从 Pending 开始。一个设备副本变为 Visible 不改变任何主机副本。

每个记录保存 selections/version、producer query/task/time、状态、caller 引用数及 in-flight 引用数。复制 Handle 值只是别名；`retain` 创建独立 caller 引用，`pin` 创建可信生产者/消费者的在途引用。每个 token 仅可 release 一次；caller 先释放时，在途引用仍可保留、完成并访问记录。两类引用都归零才回收记录；释放日志记录剩余计数和最终回收。保留 token 墓碑以诊断 Released，其他注册表的 token 返回 InvalidHandle；逻辑内容的存活期独立于模拟副本。

`try_get` 先检查 token/释放、版本、权限和位置，再返回 Failed 根因或 NotReady。成功只能来自 Visible 副本。错误包含结构化 code、可用的 query/task/time、handle/request ID 和说明。`fail` 保留传入根因，Failed/Visible 均不能重复 publish。Handles/AlgorithmView 的使用期间 ContentStore 必须存活；单 rank/线程，无并发同步。

publish/fail 是可信运行时原语，本任务没有任务状态机、continuation、服务计时或传输自动门控。探针在既有普通 data+CQ 完成回调后显式 publish，仅用于核对内容关联；正式 phase2 发布及完整 AC-04 由 M2.2 实现。句柄引用也不是缓冲 credit，容量/等待/释放计费由 M3.3 实现。

## 后端关联及验收

`ReadAssociation` 持有不可变解析计划和 query/task，校验 route/目标位置匹配（Ordinary→HostMemory，Local→DeviceBuffer）。每个 extent 绑定一个实际后端稳定 ID，完成核对 ID、LBA、sector 数和读方向；未知、重复或不匹配完成被拒绝，所有已计划请求完成前聚合结果为 false。无效输入不会发后端 I/O。它不持有后端指针，不推测完成，不自动发布句柄或分配 credit。

固定手算输入为 [m2.1-layout.json](../../../tests/fixtures/m2.1-layout.json)：vector0 位于 byte3584、长1040 B；vector1 位于 byte4624、长40 B；adj0 位于 byte16384、长12 B。选择 vector0[500,1040)、vector1[0,40)、adj0[0,12) 及重复 vector0[510,514)。结果为 LBA7×3 和 LBA32×1，共2048 B。有效请求量按 selection 重数为596 B，唯一逻辑字节为592 B；重复选择不重复请求 sector，但保留每个逻辑输出切片。每批重新解析，没有跨批/跨查询缓存。

运行 `python3 tools/archive/v0.1/verify_m2_1.py`：从根 CMake 配置/构建、全量 CTest、内容与真实后端各重复两次、Python 逐字节/sector 独立核对、ASan 两个探针和 diff 检查，原始命令/退出码/日志及哈希归档于 [证据](../../evidence/m2.1/README.md)。

后端探针复用 M1.3 `OrdinaryFixture`：SIMPLE/TURNED_OFF、固定 seed321、确定性预装载 LBA[0,512)，完全排空后发测量读。两个实际普通请求关联完成；PHY 探针在 Initialize/Setup_triggers 前注册，先于 cache 清理回调，仅复制仍有效的父请求 extent 与事务 LPA/字节值；逐项核对父请求范围以及实际 LPA/字节集合为 (0,512)、(1,1024)、(4,512)，确认跨 8-sector page 分段。之后通过 host handle 核对真实字节切片。错误矩阵覆盖范围末端、sector 边界、溢出、未知对象/版本、重复映射、释放别名、外来/空 token、位置权限、失败根因、重复/错误完成，以及在途生产者保留和最终零记录。

## 限制

本任务通过内容/布局/驻留的限定验收，未完成 M2.2 可见性、M3.2a 正式本地读取或任何完整 AC。Local 只验证 route/位置约束；没有新增设备 staging、完整在途失败清理或事务级 runtime 关联。真实 LPA 核对限探针中普通请求，生产层请求关联不提供任意 transaction/LPA 追踪。

没有改变 MQSim 或 SST Core 源码，也未重建独立原生 oracle；既有普通路径、事件桥和 SST 检查由全量 CTest 回归。ASan 两项通过不推广为上游完整泄漏审计。release 墓碑/审计日志随实验请求数增长；没有持久化 ContentStore、mmap、磁盘 layout.json 输出入口或缓存容量模型。没有校准性能参数、ANNS 搜索或两种放置性能结论。没有开始下一个任务。
