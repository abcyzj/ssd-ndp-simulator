## 实现与所有权

直接修改并编译 `third_party/MQSim`，没有构建补丁栈、另一个集成源码副本或 SST Core 改动。

- `User_Request` 的完成 route 默认仍为 HOST。普通完成分派保持原 NVMe 处理：回传数据、更新队列和普通对象清理。
- `Host_Interface_NVMe::Submit_local_read(stream, lba, sectors)` 只接受已初始化设备、已有 namespace、有效且不越界的 sector 范围，以及 SIMPLE/TURNED_OFF。调用者先将后端同步到当前权威时间。本地请求经过现有 NVMe 分页拆分，再进入现有 cache→FTL→PHY 服务路径；不进入主机 SQ/CQ，不生成普通 SQE 或主机 DMA 数据对象。其他缓存配置明确拒绝。
- 复用 SIMPLE 的汇总条件：事务列表为空且 `Sectors_serviced_from_cache == 0`。统一请求完成分派点按 route 分流；本地 route 对未完成、重复或非自身所有的完成报错，不追加第二个清理事件。
- 本地请求由 interface 的 `unique_ptr` 表独占，PHY 仍独占释放事务。最后事务的 cache/PHY 信号仍可被其他观察者访问，因此本地分派只预约同刻清理事件；信号栈返回、事务由 PHY 删除后，该事件复制 token、稳定请求 ID、字节数和完成时间，删除请求，再发布值类型完成记录。`Take_local_completions()` 消费记录，不向上层暴露已删除请求。

未对 NAND/PCIe 时间减账，也未新增第二个资源计费者。同刻清理只决定所有权与发布顺序，不增加模拟服务延迟。

## 夹具与实际验证

受控 E2 夹具使用真实 MQSim 分页、SIMPLE 汇总、PHY 完成广播/事务删除和 NVMe route。仅替换 FTL/NAND 的服务时间来源，以确定性控制两个事务完成顺序：LBA=7、2 sectors，页大小 8 sectors，拆为 page 0/1 各 512 B，bitmap 分别为 128/1。

- 乱序：page 1 在 10 ns、page 0 在 30 ns 完成；10 ns 无发布，30 ns 的 PHY 后置观察者仍能读取请求且看不到完成记录，只有随后同刻清理事件发布一次。再提交第二个请求，在 50/70 ns 重复检查。
- 正序：0→1，仍只在 30/70 ns 各发布一次；重复乱序进程的全部 E2 日志相同。
- 提前完成信号、重复完成信号均被拒绝；非法 stream、零长度、越界、字节溢出及 WRITE_CACHE 被拒绝。检查所有权表归零、完成队列再次读取为空、后端事件排空；SQ head/tail、已告知 head、CQ head/tail、在途数及等待/完成队列均保持提交前值。
- 本地夹具没有连接 PCIe switch，真实本地 NAND 探针也没有连接 PCIe。两个探针均能完成；任何普通主机发送都会访问未连接路径并导致失败。这是本轮 vector D2H=0 的路径检查，不是完整共享 PCIe 消息模型。范围内消息账本为本地 1024 B 存储读取、vector D2H=0、普通 SQ/CQ 消息=0；query/命令/结果消息尚未实现，不能从零字节推导未来端到端流量。
- 实际 SSD 探针使用 `configs/native/ssdconfig.xml` 的 tiny 配置，经过真实 FTL、映射、调度、NAND 和 PHY，完成 1 个跨页 1024 B 本地读，完成时间为 153692 ns。该探针由外部循环使用 E1 步进 API 分派，没有运行独立后端完整事件循环，也不是 SST I/O 适配验收。
- 普通 route 对照使用从 `deps.lock.json` 原生 commit 独立 `git archive` 导出并构建的 oracle，以及直接编译修改源码的开发 CLI。相同初态和固定四读输入下，两者均完成 4 读、13312 B、零写，完整结果 XML 的 SHA256 相同。开发 CLI 只作被测对象，不充当原生 oracle。

最终验收：根 CMake 配置/构建、CTest 13/13（含原有 SST E1/加载/生命周期）、ASan 后端 CTest 10/10、正序/乱序及重复运行、实际 NAND 读取、独立原生构建与普通读对照全部退出 0。ASan 使用 `detect_leaks=0:halt_on_error=1`，不包括 SST 进程；没有声称泄漏审计通过。完整命令、退出码、日志、环境、输入/配置/二进制哈希、MQSim 完整 HEAD、相对锁定原生基线 diff 哈希及实际源码逐文件哈希均保存在 manifest 中。

## 限制与后续边界

仅单设备、单进程、只读、SIMPLE/TURNED_OFF 的 PoC。真实 SSD 初态为新进程、preconditioning 关闭、初始占用 0、READ 懒建映射，保留 CMT；没有预装载/测量窗口，参数仍为 configured_unvalidated。没有实现内容存储/驻留句柄、算法运行时、近存计算/容量、query/命令/结果传输、共享 PCIe 排队、在途取消/失败回滚或同进程重复实验。支持的结束条件为先排空事件及本地请求；不承诺任意在途 I/O teardown 安全。提交到后端后发生的异常按进程失败处理，不能恢复继续实验。

受控乱序是服务边界注入，并不证明已校准 NAND 时序；真实 NAND 探针补充路径检查。普通读对照限现有四读夹具，未覆盖完整 QD/CMT/缓存配置矩阵。E2 通过不等于 AC-06、AC-08 或端到端通过，所有 AC 状态保持未运行验证。

验收运行时 MQSim 改动位于子模块工作区，主仓 gitlink 和锁定原生 commit 均未改变，源码身份以 manifest 的 diff 与文件哈希记录。验收后按用户授权提交为 `95fdb6a1085485c8b416f132c7719cc52293ad39`（`feat(ssd): add minimal device-local read completion route`），主仓随本次提交更新 gitlink；锁定原生 oracle commit 保持不变，未推送。上游 UBSan 随机数溢出、完整生命周期/泄漏审计限制继续保留。
