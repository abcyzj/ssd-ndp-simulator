# V04-4d 2/4 worker 诊断

依据 [V0.4 PRD](prd-v0.4.md) 的 N04、S04/05/08、V04 和 AC-04-07，以及[验收矩阵](validation-matrix-v0.4.md) D01/D02。使用完整 SIFT1M、锁定 NSG 图、evaluation128、L/E=64/128、k=10、B=1、语义 chunk=16。D01 为 2 worker / 2 CPU slots / 32 接纳槽，D02 为 4 / 4 / 32。

## 运行和核对

- 分别运行三次独立原生进程，使用 [原生入口](native-v0.4.md) 的 `--mode benchmark --split evaluation128 --workers 2 --concurrency 32`。D02 改用 `--workers 4`。原生基准只使用查询外层的线程 CPU 计时，详细轨迹和逐阶段插桩关闭。
- 分别运行两次 [Host 内存驻留回放](replay-v0.4.md)。显式使用 `replay`、`host_memory`、`worker-fifo/1`、绑定包和 v4 Profile，开启 `event_log`。对两个点分别设置 `native_workers`、`host.slots` 及 `max_inflight`。每个配置使用新的输出目录。
- 复用 V04-4c A02 的全量原生采集包和对应 v4 Profile。查询共享只读输入，每查询私有状态，包中没有跨查询依赖和运行 worker 分配。Validator 复验锁定输入、原始查询顺序、原生构建、分片与封包逐操作一致性、冻结模型及三次制表采样。多 worker 仅在 D01/D02 固定配额下可用 v4 表，仍检查包哈希、驻留准备条件和逐调用 Work。评估侧实测表只用于对应包的仿真执行，原生基准独立运行。
- 全量逐查询以独立 Python oracle、同构建 Host direct/动态 IR 参考核对决策、逻辑访问、真实值、Work 和终态。detail8 参考另做对应核对，报告保留这八条的原生和模拟时间线以及全量摘要。重算 FIFO 接纳、worker 领取和占有、等待、CPU 服务并发峰值和排空。模拟重复比对实际事件、模拟时间、统计、账本和结果，宿主墙钟与 RSS 单列。
- 报告分别提供每次原生基准、三次的中位数和范围、模拟值及有符号偏差。占用按 CPU 时间除以批次窗口与 worker/slots 数的乘积计算。原生 worker 占有期间的墙钟减线程 CPU 仅反映聚合差额，包含调用及发布开销。原生和模拟的实际 worker 分配允许不同。

## Validator

用与 [V04-4c](level-bc-v0.4.md#入口) 相同的输入参数，将 `--native` 和 `--replays` 指向对应点的新运行，再加 `--workers 2` 或 `--workers 4`。继续传入 A02 的未插桩单 worker 语义对照、完整采集包及三次制表 Measurement，并提供同模拟构建的全量及 detail8 Host direct/动态 IR 参考。新输出目录生成 `workers.json`、`workers.md`、`queries.csv` 和 `detail8.json`。证据缺失、身份、语义、确定性或资源核对失败均退出 1。2/4 worker 的性能差异无百分比门槛。

冻结单 worker 服务需求在多 worker 中作为诊断输入。缓存和内存带宽竞争、OS 抢占、异构核分配没有单独建模，核绑定和频率未控制，硬件缓存计数器为 Unsupported。报告中的 CPU 与等待差异无法归因到单一硬件或调度因素。SSD、PCIe、Controller 仍为 `configured_unvalidated`。

D01 原生 QPS 范围 102.48–102.88，D02 为 197.29–198.32。2 到 4 worker 的吞吐倍率为原生 1.93×、模拟 1.96×。模拟总服务需求相同，原生 CPU 总量中位数增加 1.74%。原生批次的 minor fault 范围为 15–29，major fault 均为 0。D01/D02 的原生累计 worker 等待中位数为 32.308 / 15.321 s，模拟为 31.530 / 14.688 s。这里的累计等待是逐查询之和。CPU 阶段的依赖等待、CPU 队列等待均为 0。

模拟 QPS 较原生中位数高 2.50% / 4.17%，总 CPU 服务需求低 2.39% / 4.06%。原生 worker 占有墙钟与线程 CPU 的累计差额范围分别为 0.048–0.067 ms 和 0.261–0.899 ms。模拟 CPU 成本固定，原生总 CPU 和占用随 worker 数变化，这些观察保留为本机诊断差异。

## 复核与证据

D01/D02 各三次原生基准、两次模拟均退出 0。每点两次模拟的事件、结果、统计和资源账本一致。两点全部 128 查询的实际值、路径、Work 和终态均通过独立核对。模拟 CPU 服务峰值分别为 2 和 4，两个点接纳峰值均为 32，排空后无在途服务或等待。AC-04-07 通过。

根 CMake 配置、`-j2` 构建、CTest 91/91、修订后的两个定向 CTest、Python 语法及 `git diff --check` 均通过。对既有 A02 产物重新执行单 worker Validator，通过原精度门槛。用本次构建新跑四组 Host direct/动态 IR 参考，覆盖 evaluation128 和 detail8。结果、语义轨迹、服务账本及查询和 top-k 导出与 V04-4c 对应参考逐字节一致。改动限定于显式 v4 驻留回放的表适用性和离线核对，本轮未触发 52 条深度回归。完整继承 AC 与 V0.4 总验收仍有独立出口。

完整规模运行前重新核验输入及哈希、物理内存和磁盘预算。成功回放前预检空闲内存比例为 54%，可用磁盘约 65 GiB。回放每次设置 600 s、2 GiB 输出及 4 GiB SST 子进程 RSS 上限。四次 SST 子进程墙钟为 20.38、21.04、20.85、18.41 s，峰值 RSS 约 786–795 MiB。原生每次设置 300 s、1 GiB 输出及 4 GiB RSS 上限。

本机证据位于 `results/v0.4/workers-v044d/`，含 `evidence.json`、实际命令、退出码、配置、输入/源码/依赖/构建身份、原始产物、断言及 SHA256。首轮回放因沙箱限制无法读取本机身份。获得读取权限后，首次 SST 回放暴露 v4 表的单 worker 限制。修正后在新目录完成正式回放。失败样本和单 worker Validator 回归的修订前输出均保留。
