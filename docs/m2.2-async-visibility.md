# M2.2 异步依赖与可见性

2026-10-28（Asia/Shanghai）。依据 FR-01/02、M0.4 冻结契约与 M2.1 内容/句柄；前置任务 M2.1 已有根 CMake、20/20 回归、ASan 和实际普通 I/O 关联证据。本任务没有改变范围、时间模型或资源归属。

## 实现

`src/runtime/runtime.{h,cc}` 提供 C++17 显式任务状态机和 continuation。算法仅接收不透明结果 `Handle` 及 `View::try_get`；`Runtime`、`Operation` 和完成入口供受信适配层使用。任务的结果位置和执行器输入权限分开检查。

任务经 Submitted、WaitingDependencies、WaitingResource、Running、ServiceDone，以及必要的 WaitingReturn，最终 Visible；失败进入终态 Failed。任务 ID 在进程内递增且不复用。输入在资源 grant 之后只计算一次，输出放入私有 Bytes 槽。功能执行及任何宿主机墙钟耗时不推进模拟时间。服务与返回适配器分别报告实际完成，运行时只在既有 EventBridge 的 Publish 阶段开放数值，不增加服务费或传输费。无返回路径也不内联发布。

`when_all` 等待所有副本 Visible，失败则异步传出原始 code/query/task/handle/time/detail/causal_parent。空集、已经就绪集合、重复输入均排队一次，回调在 ContinueSubmit 阶段运行。每次注册有独立内部 wait ID，外部 continuation token 用作关联标识，不与 TaskId 共用名字空间。提交只能引用已存在任务的句柄，因此不能构造未来依赖或循环；无需静态完整 DAG，回调可以按真实返回值继续提交。

结果句柄独立于 M2.1 的逻辑对象句柄：前者保存计算产生的值及可见性，后者保存不可变对象范围、版本、布局和驻留引用；运行时不会在 ContentStore 内伪造新对象。后续 read 适配器仍须使用 M2.1 的对象验证、引用及请求关联，不能用此处的 Bytes 回调绕过存储/传输边界。当前 `submit(Operation)` 是受信集成原语，不宣称 read/invoke 的最终应用门面已经完成。

复制 token 不新增所有权；retain 取得独立 lease，release 使同一 lease 的所有复制失效。producer pin 在终态释放，consumer 对输入保持独立所有权直至功能执行结束，等待器另持 pin。失败清除私有结果并释放输入；已无 owner/pin 时释放 payload。保留少量任务状态及失败元数据供诊断，尚未做长实验历史裁剪。单线程下等待无需锁、sleep 或阻塞 SST。

未知/外来/释放句柄、权限错误、重复/乱序完成在入口明确拒绝；NotReady 不当作失败。功能、资源或返回适配器异常转为失败；失败沿依赖传播，后继不获资源也不执行功能。已失败任务不能被排队的旧提交回调重新启动。服务/返回的迟到、重复完成报错，不能变成成功结果。

`require_progress` 结合桥的队列状态检查：有未完成任务/等待器但无未来事件即 Stalled，列出 query/task、状态、依赖任务状态、引用数、等待资源说明及 EventBridge 时钟/generation/最近因果链。桥已有同刻事件上限继续防止零时间活锁。尚无 BufferModel，credit 数值无法提供，不将零伪装成真实可用 credit。
