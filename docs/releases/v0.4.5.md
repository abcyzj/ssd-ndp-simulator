# V0.4.5 发布验收

依据 [PRD §6](../prd-v0.4.5.md#6-验收标准) 和 [实施计划 P21](../implementation-plan-v0.4.5.md)。交付包含 timing-only 模拟器、独立图搜索与采集 SDK、独立 Python 拟合工具、三层 Validator 和教学扩展。支持单 SSD 的 Host／Controller 放置，以及无 SSD 的 Host 驻留。验证平台为 macOS 26.5.1 arm64。

## 干净目录复现

获取本仓库及锁定子模块，例如在新目录执行 `git clone --recurse-submodules <repository> source`。使用 [依赖锁](../../deps.lock.json) 指定的 Xcode Command Line Tools、CMake、Python 及匹配的 python-config、autoconf、automake、GNU libtool、m4、make。Python 安装需要 setuptools ≥77、jsonschema 和 referencing。根构建会从干净的 SST Core Git 检出独立导出锁定源码并构建 SST，依赖源请保留 Git 元数据。普通构建只需 fork 的锁定提交，独立 MQSim 对拍另外需要原生基线提交可在 MQSim 仓库中解析。许可证见 [主项目](../../LICENSE)、[Python](../../python/LICENSE)、[MQSim](../../third_party/MQSim/LICENSE) 和 [SST Core](../../third_party/sst-core/LICENSE.md)。

以下在新检出的源码根目录运行。选择具有上述依赖的 Python，并为新构建预留磁盘。将 `out` 指向一个空目录。SST 缓存、Python 安装、构建和输出均可留在该目录。

```sh
out=$(mktemp -d)
py=$(command -v python3.13)
"$py" -m pip install --target "$out/python" ./python
export PYTHONPATH="$out/python"
ndp="$out/python/bin/ndpsim"
"$ndp" --help

# 隔离原生工程。Python SDK 与算子契约是采集测试的显式依赖。
cp -R workloads/graph-search sdk "$out/"
cp extensions/graph/operators.json "$out/operators.json"
cmake -S "$out/graph-search" -B "$out/graph-build" \
  -DNDPSIM_SDK_ROOT="$out/sdk" -DBUILD_TESTING=ON \
  -DPython3_EXECUTABLE="$py" -DNDPSIM_GRAPH_CAPTURE_TESTING=ON \
  -DNDPSIM_GRAPH_PYTHON_ROOT="$out/python" -DNDPSIM_GRAPH_OPERATORS="$out/operators.json"
cmake --build "$out/graph-build" -j2
ctest --test-dir "$out/graph-build" --output-on-failure

# 新 SST 缓存和模拟构建。
cmake -S . -B "$out/build" -DBUILD_TESTING=ON \
  -DPython3_EXECUTABLE="$py" -DNDPSIM_SST_CACHE_DIR="$out/sst-cache"
cmake --build "$out/build" -j2
ctest --test-dir "$out/build" --output-on-failure
"$py" examples/extension/tutorial.py \
  --native "$out/build/examples/extension/block_sum_native" \
  --device "$PWD/configs/devices/native-small.xml" \
  --build "$out/build" --output "$out/tutorial"
"$ndp" check --package "$out/tutorial/package" \
  --registry examples/extension/operators.json --report "$out/check.json"
```

教学流程真实计算并采集三项操作，独立核对两个并行分支及汇合，然后移走业务输入，运行真实 SST 双映射。检查 `tutorial/semantic.json`、`tutorial/comparison.json` 和逐事件轨迹。独立拟合只使用 Python 包和元数据，可在安装后直接执行 `ndpsim fit`。输入格式及独立安装见 [拟合指南](../../python/FITTING.md)。统一运行、配置及报告解读见 [CLI](../../python/CLI.md)、[配置](../../configs/README.md) 和 [Validator](../../python/VALIDATION.md)。

## 正式输入和执行日程

1. 从 [数据锁](../../configs/benchmarks/datasets.lock.json) 指定的公共来源取 SIFT1M，核对原始四文件 SHA256 和长度。按 [导入规范](../data-v2.md) 使用 `tools/benchmark_data.py import` 导入完整 base、查询及官方真值。查询与真值逐切分使用 [原始 ID 清单](../../configs/benchmarks/v0.2-query-selection.json)，保留 ID 和顺序。
2. 依 [离线准备](../index-truth-v2.md) 构建锁定 Faiss/OpenMP 的建图器并生成 receipt。此次使用 `tools/benchmark_artifacts.py build <prepared-tuning32> <index> --receipt <builder-receipt> --threads 1 --timeout 28800`，以 `check-index` 核对完整图，再为两切分各执行 `official <prepared> <truth>`。复核实际图及 receipt，不能将多线程重建结果视为同一输入。记录的图为 1,000,000 节点、29,975,972 条边、入口 123742，图 SHA256 为 `440d281c378e044aa53f6943e9dee274854af33b109f2725b270a9f8c5ce4142`。
3. 按 [采集配置](../../workloads/graph-search/CAPTURE.md) 引用 prepared vectors/queries、原始 ID 文件、图邻接、官方真值和内容哈希。两正式点为 L/E=32/64、64/128，k=10、B=1、chunk=16、worker/slots/admission=1/1/1。先跑合成 pilot 和三组 tuning32 A/B/A。五个 tuning32 点按 [配方三版](../../extensions/graph/fit-recipe-v3.json) 采集和训练。两主点分别追加三个 stride=1 表采样，冻结预测 Profile 和低信号两情景，随后执行 evaluation128 采集、每点三次表采样和三次独立 benchmark。
4. 用 `ndpsim fit` 生成训练、表和评价证据，以 `ndpsim simulate` 在每个 A 点运行两次零情景、一次参考情景。两 tuning32 点也各运行两情景。用 `ndpsim verify` 核对预测阶段、表绑定、调度与唯一计费。按 [P18 日程及预算](../resident-accuracy-v0.4.5.md) 记录 RAM、磁盘、输出投影和超时。每个失败保留原输出，在新目录重试。
5. 依 [P19 参数](../ssd-accounting-v0.4.5.md) 对相同 evaluation128 包完成四个 SSD 运行，固定各对的外置 XML、Layout、配额和资源。验证逐项账本后，使用 `ndpsim compare` 各比较 B01/C01、B02/C02。对拍另运行 `python tools/verify_mqsim.py --build <test-build> --output <new-oracle-dir>`，保留独立原生导出、两边请求和四组双重复。

## 证据汇总

P21 对正式矩阵使用 P20 清理后重新执行的八次正式模拟，以及同身份的驻留参考情景、tuning32 账本和原生 MQSim 对拍。正式训练、完整采集和 benchmark 复用 P18/P19 中已登记、逐文件复核的当版证据。P21 新增的工具和文档位于模拟器、原生和拟合执行路径之外。P20 执行文件在当前工作区及干净构建源码均逐项匹配，依赖、原生及模拟二进制也已核验。没有沿用 V0.4 或更早的验收结果。

发布汇总入口 `tools/verify_release.py` 消费本次 P17～P20 的证据格式，要求显式指定证据根、干净执行记录和干净构建目录。它是发布记录的审计器，正式日程由上面的各入口生成。当前审计器使用本次阶段目录布局。归档移动后可以用 `--formal-root` 选择保存正式构建文件的根目录，保留记录中的相对布局；另一轮运行需生成该轮的阶段证据索引。最小工作流与正式运行入口均可选择自己的输出目录。

```sh
python3.13 tools/verify_release.py --evidence <stage-evidence-root> \
  --clean <clean-command-logs> --workspace <clean-build-workspace> \
  --output <new-acceptance-directory>
```

本轮记录在 `results/v0.4.5/p21/`。最终 `release/manifest.json` 为 12/12，退出 0，SHA256 为 `d47d23c2099bfadda37ca92adb123f6d777877cb203ce640dbd98a7475ff6308`。其中 `clean2` 保存 `clean.sh`／`isolated.sh`、逐命令日志和退出码。干净检出从当前源码的 Git 归档和本地 Git 子模块克隆准备，全新 SST 缓存独立构建。第一轮使用纯源码子模块归档时 SST 配置退出 1，日志保留在 `clean1`。第二轮根 CTest **82/82**，隔离原生 CTest **4/4**，独立 Python 拟合 **17 通过、3 项 C++ 消费检查在该隔离环境跳过**。三项消费检查由根 `independent_fit_v045` 覆盖。教学双映射和安装后 `ndpsim check` 均退出 0。干净构建另重跑独立 MQSim 对拍，四组各两次原生和两次 SST 均通过，见 `clean-oracle/manifest.json`。迁移库存复核覆盖 251 个文件和 82 项 CTest。

P20 的 `seal.log` 在外层 stdout 重定向仍未写入时被 P20 清单哈希为零字节。P21 核对它实际输出的 JSON 与 P20 清单 summary 完全一致，并独立记录实得哈希。其余登记文件严格比对原有哈希。保留前期聚合失败日志。缺文件、改文件、quick、失败状态和旧阶段替代共五个负例，均退出 2，记录 `full_acceptance_passed=false`。
