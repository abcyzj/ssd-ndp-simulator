# V0.4 验收矩阵：14 个模拟配置

日期：2026-11-03（Asia/Shanghai）。按用户确认，将 V0.4 常规完整规模验收收敛为 **14 个模拟配置**，V0.3 的 52 条矩阵保留为按需深度回归。本文为待实施规范，不表示新验收入口已实现或任何实验已运行；需求与任务见 [PRD](prd-v0.4.md)、[实施清单](implementation-plan-v0.4.md)。

本轮按修订PRD将A/D/O十个配置改为静态IR执行，R四个兼容配置继续使用旧direct/动态ir。内存驻留 `replay` 已实现，逐调用制表、回放查表与单点 Validator 核验已实现。完整采集和矩阵汇总仍待执行。配置数量和深度回归触发规则保持。

## 配置与计数

所有正式配置使用完整 SIFT1M 1,000,000×128 base、同一锁定 NSG 图/真值及固定 evaluation128；k=10、B=1、语义 chunk=16。主配置为 L/E=128/256。Controller 实际 chunk 仍按既有容量规则决定并逐块记账，不为凑配置数改变模型。

“配置数”指下表独立的模拟参数组合，**不等于进程执行次数**。native 不属于这14个模拟配置；同配置重复、日志诊断、训练采集、A/B/A、开工smoke和定向测试均另计。报告必须同时列出配置覆盖数、实际执行次数、完整IR采集/诊断及继承测试次数，不能把所有工作描述为“只跑14次”。

## CPU 实测查表与整机评价

- tuning32 仍用于拟合和模型选择。首批查表阶段为 `merge_append`，其他难预测阶段须逐项写入版本化清单。正式采集前冻结清单、CPU 桶、计时质量规则、重复归约规则和其余阶段的模型。清单变更须升版并披露已看过的评价结果。
- 四个 L/E 点均在 tuning32 和 evaluation128 上单独采集清单阶段的逐次调用线程 CPU 耗时，保留原始重复、探针开销和质量标记。表按切分、运行条件和 L/E 分别生成，查表阶段须覆盖全部调用。通过原始 query ID、稳定操作/阶段及调用序号定位，并核验实际 Work。表绑定输入、静态包、构建、采集配置及硬件/驻留/worker 条件，记录测量与表的 hash。缺项、重复键、低质量证据或身份/Work 不符时失败关闭。
- A01～A04 用对应的 evaluation128 表提供已列名阶段的 CPU 服务需求，其余阶段用适用的冻结模型。查表只提供服务时长，SST 仍按真实输入、依赖和资源调度并核验实际结果。D/O 只有在各自条件匹配时才能使用实测表，须另采适用表或显式采用该条件下适用的模型，缺少适用成本则报告失败或 Unsupported。
- evaluation128 用于给定实测 CPU 成本的整机对拍。原生对拍基准独立运行，不使用制表运行作为精度基准。AC-04-04 正式验收仅覆盖 L/E=32/64、64/128（A01、A02），两点均须通过；128/256、256/512 的 Level A 结果作为诊断。四点实测表仍按对应回放配置采集。AC-04-04 对查表阶段核验覆盖、计时质量、Work 及唯一计费，报告标明实测来源和 CPU 占比。模型误差门槛只用于仍由模型估计的阶段，复用表值不计作预测精度证据。允许复用已暴露的评价结果，须披露既有暴露并保持原始 query ID 切分和评价数据禁止回流拟合。AC-04-05/06 仍按全部正式点判定，报告须披露已使用 evaluation128 实测输入及既有评价暴露。

## 重复、详细样本与覆盖复用

- A01～A04的对应原生基准每点至少3次；D01/D02对应原生基准每点至少3次。至少有18次原生性能测量，训练、A/B/A及详细采集另计。保持模型训练与评价数据隔离，另计制表采集；主要/短算子分类和整机精度门槛保持。
- A01～A04、D01/D02在同输入/配置下至少2次模拟执行，核对结果、决策、Work和模拟统计的确定性，宿主墙钟/RSS另报。这些是重复次数，不新增配置。R/O每配置至少1次成功运行；异常/失败重跑保留全部证据。
- A/D/O执行输入必须包含该配置全部evaluation128的完整操作/依赖/终态；四个L/E分别采包，D与O可按PRD §6.4.3复用主配置每查询语义包，B/C使用同包而由运行时生成各自物理分块。评价包和制表测量在清单及预测模型冻结后采集，评价数据禁止回流训练。静态包、索引、校验临时文件和采集运行单列预算/次数；模型样本可采样，查表阶段和执行 IR 均要求完整覆盖。
- detail8仅用于额外语义/资源详细诊断；全evaluation128仍留结果、决策及实际Work摘要。A03、D01/D02、R01～R04、O01～O04的详细关联按相关出口采集；同身份已有完整包和诊断证据可分别严格复用。详细开关与统计等价先由定向用例验证；必要的detail8伴随运行单列，不把其Q=8结果计作evaluation128正式结果。
- native无插桩/采集/静态执行在A01～A04做完整base四点语义/实际工作量和精度核对；完整base的direct参考集中在主配置R01/R02。A03与R组建立原生/静态执行/direct/动态ir语义关联，只在同旧成本的R01/R03、R02/R04间严格比较模拟时间和资源。其余L/E的direct语义保留小夹具/真实子集四点及独立oracle核对，避免额外扩成完整base的四点×engine×placement。
- 兼容组核对冻结参考及本轮重构前参考。省略engine应有效ir，省略新增Profile/驻留字段仍走原SSD/成本；省略与显式配置的入口等价由定向测试/必要smoke证明。冻结参考缺失或身份不符不得以历史passed代替。
- 同一成功运行可同时支持语义、精度、资源和兼容报告，不为每个AC重复启动实验。复用必须核对实际执行/验证源码、构建、依赖、输入、配置、静态包、Profile、实测表及其采集身份、执行策略和全部登记产物 hash；改过相关身份就重跑，不能凭输出目录名或配置名复用。

静态执行须补充定向小夹具：同逻辑输入、旧成本及同一SSD映射策略下，replay与direct/动态ir的结果、模拟时序和资源账本严格等价；A的worker串行策略另按原生口径核对。身份/缺查询/截断/依赖/状态/重算值与Work失配、延迟门控、未来地址旁路、旧包拒绝与重采均为必需负例，不新增全规模配置。原生插桩来源和独立oracle不能由“输入包摘要等于输出摘要”替代。

仅表中最低次数已需20次模拟执行（A/D的6配置各2次，加R/O的8配置各1次）；该数字仍不包括detail8、开工smoke、因果探针、继承测试或触发的深度回归。**14是常规验收的固定配置基线，不是对全部运行次数的承诺。**

下列任一情况触发深度回归：

1. 搜索语义/数值/Work、旧默认计费、事件/发布顺序、默认存储或传输路径发生实际变化，或无法用源码与定向证据排除这些影响；仅文件被修改不自动触发。
2. 14配置或定向测试出现无法解释的结果、时间、账本、确定性、内存增长或效率异常，影响可能跨配置。
3. 修改MQSim/SST依赖身份、共享布局/设备模型，或改动触及既有完整矩阵门槛本身。

V04-5b保存 `regression-impact.json`（建议名）：改动及影响范围、触发条件逐项判定、依据、所跑/复用配置和定向测试、深度回归是否需要/已完成及证据。未触发记“本轮不要求”，不计深度回归通过；已触发而未跑或失败，阻塞相关兼容出口和V0.4总交付。深度运行源码身份仍适用时可按既有严格规则复用，无须每个后续阶段重复；涉及相关变化则失效。
