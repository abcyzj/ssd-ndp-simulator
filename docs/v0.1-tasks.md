### 1.3 结论—证据索引与复核边界

2026-10-26 核对的三个上游提交与原核查均无变化；2026-10-27 已初始化的 SST Core 和 MQSim fork 也采用相同基线。原规划具有固定提交源码证据的其余静态结论沿用；本次归档仅补核与事件因果、请求汇总和本地路径有关的关键边界。使用相同提交且无相关补丁时沿用这些结论，仅复核版本变化、补丁影响或证据不足的关键结论。本机 macOS 原生构建和小读证据已由 M0.2 补齐；事件桥和生命周期验收仍待后续任务。

| 结论 | 固定提交源码证据 | 证据能证明什么 | 尚缺的运行证据与任务 |
| --- | --- | --- | --- |
| MQSim 没有可直接调用的外部步进接口 | [Engine.h 的公开接口][engine-api]、[Start_simulation 与集成开关][engine-loop] | 原引擎将初始化和完整事件循环放在 Start_simulation；Is_integrated_execution_mode 返回 false；桥接 API 仍需新增 | E1、正式桥接和原生对照；M0.3a、M1.2、M1.3 |
| 同刻事件与忽略语义必须保留 | [EventTree 插入同刻事件][event-insert]、[引擎分派及 Ignore][engine-loop] | 同刻事件尾部追加；原循环检查 Ignore 并释放事件 | 外部插入、回调新增同刻事件、过期唤醒仍保持因果；M0.3a、M1.2 |
| 单个 NAND 子事务完成不等于完整请求就绪 | [请求完成条件][request-finished]、[SIMPLE 缓存管理器汇总][cache-complete] | 完成条件同时检查剩余事务及缓存服务；子事务从请求列表移除后才判断和广播请求完成 | 跨页乱序完成、一次发布、错误清理；M0.3b、M3.2a |
| 普通读取完成会回传完整读取数据并更新 NVMe 队列状态 | [统一缓存完成分派][completion-dispatch]、[NVMe serviced 路径][nvme-serviced]、[Send_read_data][send-read-data] | 现有分派进入普通 NVMe 路径；READ 调用 Send_read_data，后者发送 Size_in_byte；本地 route 不能只增加观察者 | 本地读取无向量 D2H、无普通 SQ/CQ 副作用且生命周期正确；M0.3b、M3.2a、M3.2b |
| 上游组合构建、时序等价与观测可信度仍未证明 | 原规划§2、§10、§13明确保留未验证状态 | 现有记录是静态核查、源码准备和设计，不是构建、PoC 或 AC 通过记录 | 本机 macOS 构建、E1～E5、AC-01～AC-11；相关任务见§2和§5 |

SST、PCIe、真实内容、初态及 DiskANN 复用等已有静态依据继续引用原规划§2、§7～8及其固定提交链接。没有证据表明已经存在可用 SST–MQSim 集成、可靠本地路径、资源模型或算法实现。以上复核不能证明可构建性、生命周期安全、性能等价、资源参数校准或仿真验收通过。
