# M3.2b 共享 PCIe 传输

2026-10-28（Asia/Shanghai）。依赖 M3.2a 的正式本地存储服务已完成；沿用 M0.4 消息格式版本 1、FR-06/07 与唯一计费边界，不改变原生 NVMe 编码、带宽公式或整数 ns 取整。仅完成共享传输与端点协议原语，不开始 M3.3。

## 实现与接口

- `src/transport/messages.{h,cc}`：七种 envelope 逐字段 little-endian 编码，48 B 公共头；FP32 query、uint32 IDs、packed uint32 ID + FP64 distance，无 C++ padding/指针。双向约束、长度/count、reserved、schema、状态、维度、非有限数、重复 ID 等在发送前及接收到达时核对。超出 MQSim signed-int wire 字节上界的消息拒绝，不分片、不重试。
- `src/transport/pcie.h`：`PcieTransport::send(Message, Receive)` 返回稳定 MessageId，保存 query/task、useful/payload、发送与到达时间及完成状态。发送方必须先把 MQSim 同步至 SST now。envelope 字节保留至实际链路到达，完成回调进入 EventBridge ResourceCompleteRelease；零 ns 也不内联完成。`pending()` 用于排空/停滞诊断。
- `src/transport/conversation.h`：端点在到达后调用 `Conversation::arrive`，验证 query/token/task/chunk 归属、维度、结果数与 ID 顺序、ACK 回显、重复响应、关闭前请求排空。此状态不管理设备 credit、staging 或算子。可信发送 API 不提供任意损坏封包的在线注入；不合法 envelope 在提交前拒绝。可解析的业务错误由端点发出 Error envelope，照常计费；协议身份无法关联则抛错，不能伪造成功响应。Score 错误只返回 Error，不返回部分成功结果。
- `third_party/MQSim/src/host/PCIe_Message.h` 和 `PCIe_Link.{h,cpp}`：新增 PLATFORM 类型及端点分派，直接复用原来的两个 `Message_buffer_*` FIFO。普通 SQ/CQ、doorbell、DMA 与平台消息同向共享排队，双向独立。原生 endpoint 分派保持不变；PLATFORM 不进入 NVMe 消费器。链路观察提供稳定 link ID、platform ID、方向、原生类型、入队/开始/到达、payload、wire 与服务时间，按 platform ID 关联 query/task。
- 链路到达期间若端点向同方向队列追加消息，`delivering_*` 保证队首只预约一次。新增平台消息生命周期/服务溢出诊断；销毁适配器后不会调用过期端点，链路销毁回收未交付的平台 envelope。异常仍按 V0.1 终止实验，不承诺在途取消后恢复。

唯一链路服务仍为 MQSim：`wire=P+ceil(P/128)*28`（READ_REQ 为 32 B），默认 `floor(ceil(wire/4)/lane_GBps)` ns。SST SelfLink 只调度，不附加序列化带宽/传输费。原生 sizeof(SQE)=72 B 保留。配置为人工未校准值 `configured_unvalidated`；wire 是 MQSim 模拟公式量，并非完整实际 PCIe 协议。

## 运行与验收

根目录复现：

```sh
python3 tools/verify_m3_2b.py
```

脚本经根 CMake 配置/构建 `build/m3.2b`，再执行完整 CTest、真实 SST、隔离契约探针、ASan 与独立锁定原生 oracle 回归。命令、退出码、源码身份及输入/日志 SHA256 见 [manifest](evidence/m3.2b/manifest.json)，完整索引见 [证据](evidence/m3.2b/README.md)。也可读取构建生成的 `sst-paths.json`，使用其中的 sst 和 `--add-lib-path=build/m3.2b configs/m3.2b/pcie.py` 单独运行混发场景。

固定输入：native-small、SIMPLE/TURNED_OFF、CMT 保留，确定性预装载 64 sectors 后排空；两个 512 B 普通读 LBA7/16；d=32 query=1.25，Score IDs=[4,8]、packed results=[(4,25),(8,5)]；另一个 Score 由夹具端点返回 Unsupported Error。这里的结果是传输夹具，未声称实现盘控 L2。Runtime 私有结果先就绪，必须等真实 ScoreResult 到达才可见。八条 envelope 覆盖七种 kind，Close/Ack 与普通 CQ doorbell 均继续计费并排空。

实测共享账本（分别汇总实际消息，不机械按读请求数推算）：

| 来源 | H2D payload / wire B | D2H payload / wire B |
| --- | --- | --- |
| 普通 NVMe，两个读 | 152 / 320 | 1064 / 1400 |
| 平台，八条 envelope | 380 / 520 | 224 / 336 |
| 合计 | 532 / 840 | 1288 / 1736 |

平台语义 useful=164 B，传输 envelope payload=604 B、wire=856 B。全链路 payload=1820 B、wire=2576 B，账本各层分列，不重复收费。逐消息服务开始满足 `max(enqueued, previous_same_direction_arrival)`，到达满足 `start+native_service`。query 在 H2D 等待普通 doorbell 8 ns；普通 H2D doorbell 也等待 query，结果在 D2H 等待普通 DMA 175 ns。结果在相对预装载结束 77151 ns 到达并发布，提前可见探针拒绝；整个实验包含第二个普通读及尾部控制消息排空。

隔离链路每条 H2D payload=72 B/wire=100 B，D2H payload=48 B/wire=76 B。lane_GBps=1：H2D 25/50 ns、D2H 19 ns；=2：12/24 ns、9 ns；=1000000：三条均 0 ns，仍异步、无重复/死循环。额外验证端点同方向重入和适配器提前销毁。

## 限制

完成本任务的 E3、共享队列、流量守恒、到达完成及普通读基线范围。端点处理默认 0 ns，未实现 staging/credit/缓冲服务、盘控计算调度或设备 query 内容驻留；这些仍属于 M3.3。Conversation 由端点显式调用，低层传输器不承担设备业务状态。消息记录为实验内存账本，完整可配置 JSON/CSV/日志与并发实验输出仍属 M4.1。没有启动完整两放置图搜索或完整 AC-01～11 集成验收；不声称绝对性能已校准、盘控更快、共享 DRAM 竞争已建模或完整上游泄漏审计通过。

MQSim 直接在子模块内修改；manifest 同时记录 HEAD、相对 deps.lock 原生基线的 diff SHA256、相对 HEAD 的 diff SHA256 和实际逐文件 SHA256。没有提交、推送或更新 gitlink，后续提交须先保存 fork 源码再更新主仓。
