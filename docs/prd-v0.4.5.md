## 1. 产品目标

将现有图搜索仿真工程整理为可供其他研究者和开发者使用的平台。用户应能够清晰完成以下过程：在自己的真实业务程序中采集完整静态 IR，定义算子、工作量及依赖关系，提供硬件成本模型和映射规则，选择部分算子下沉，并取得可解释、可追溯的时序、流量和资源占用结果。

V0.4.5 仿真器只支持 timing-only：不执行业务功能计算，不保存或读取业务真实 payload；通过已采集的访问、工作量和依赖，模拟服务与资源竞争。真实业务执行、功能正确性、采集和测量位于仿真器之外。现有图搜索成为独立构建的参考负载和接入示例，不再定义平台核心的通用语法。

主要用户为业务负载开发者、算子开发者及存储架构研究者。交付重点为清晰的扩展边界、可独立使用的工具、可修改的运行配置和可复现的验证；不承诺任意负载自动接入、任意硬件预测准确或下沉必然更快。

## 3. 范围与非目标

### 3.1 必须交付

1. 单一 timing-only 仿真执行路径，支持 Host 内存驻留和现有单 SSD Host／Controller 映射。
2. 独立图搜索工程，保留 benchmark、CPU 测量及完整静态 IR 采集能力。
3. 通用静态 IR 契约、采集接口、校验工具及图搜索扩展。
4. 可扩展的算子契约、映射接口、成本模型接口和独立拟合工具。
5. 运行时加载的 Layout、MQSim 设备配置、资源配置、Profile 和放置策略。
6. 统一用户入口、入门教程、扩展示例及新的验证入口。
7. 当前数据标准下的原生／驻留精度对拍、独立 MQSim 行为对拍及必要基础测试。
8. 不依赖维护者本机历史 results 目录的发布和复现流程。

### 3.2 本版不做

- 任意程序的自动插桩、通用编译器、自动依赖推断、自动算子融合或自动放置搜索。
- 由竞速、超时、取消或时延改变控制流的反事实仿真；通过固定轨迹模拟改变数值语义的下沉。
- 可写业务对象、共享可变数据一致性、多主机、多 SSD、新硬件执行位置。
- DiskANN/PQ、Deep10M、第二个正式精度负载、精细 Cache/DRAM/NUMA/OS 模型。
- 真实 SSD、PCIe、盘控硬件校准或跨硬件 CPU 精度保证。
- 动态插件装载、稳定跨语言 ABI、完整故障恢复；首版可使用编译期扩展注册。
- 旧引擎、旧配置及旧脚本的长期兼容层。

## 4. 架构与职责边界

```text
真实业务程序 + 功能算子 + 采集／测量接口
    ├── 完整静态 IR ── 离线校验 ─────────────┐
    ├── Measurement ── 独立拟合工具 ── Profile │
    └── 原生 benchmark／功能参考              │
                                             ↓
         算子契约 + 映射规则 + Layout + 放置／硬件配置
                                             ↓
                   timing-only 依赖执行与资源调度
                                             ↓
                         SST + MQSim
                                             ↓
                   时序／流量／资源报告与对拍
```

| 模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 业务程序／功能算子 | 执行真实算法，产生真实访问与 Work，采集功能证据 | 推进模拟时间 |
| 采集与校验工具 | 导出完整依赖及元数据，验证包完整性、语义与适用条件 | 用哈希代替功能正确性证明 |
| 算子契约 | 定义名称、版本、端口、Work 特征、输出大小及支持位置 | 将硬件服务公式写入业务算法 |
| 映射层 | 把逻辑算子降低为读取、传输、缓冲、计算和返回步骤 | 绕过资源所有者直接完成服务 |
| Cost model | 根据特征、位置及上下文估计服务需求 | 管理排队或建立第二套事件引擎 |
| 执行与资源层 | 依赖放行、仲裁、排队、服务完成、返回和释放 | 重算业务结果或使用宿主墙钟作模拟耗时 |
| SST／MQSim | 统一时间及现有设备／链路资源仿真 | 接受未经声明的新硬件能力 |

模块须能通过独立接口接入。最终目录、类名和文件名由后续实施计划确定，本文不预设实现细节。

## 5. 功能需求

### FR-045-01 Timing-only 执行

正式模拟运行不得要求向量、图、查询等业务 payload 文件，不得调用 L2、排序、去重或其他真实业务计算。可以持有对象描述、逻辑地址、Work、输出大小、摘要、依赖令牌和必要的模拟协议元数据。

“不做实际存储”不等于删除 MQSim 的 FTL、缓存、队列、NAND 状态、地址映射或初态准备。须保留正确时序所需的预装载／预处理和排空，记录测量窗口；不要求业务数据真实落盘。内容字节、逻辑大小、LBA、sector/NAND/PCIe 字节和目标驻留必须分开。

依赖满足后才能提交对应服务；已知未来访问不授予提前读取、预取或资源预占权限。输入就绪、计算服务及必要返回完成前，不发布完成令牌或释放后继。零时长与空操作仍遵守异步执行。模拟时间不依赖采集时间戳、宿主功能执行速度或报告生成时间。

### FR-045-02 独立图搜索参考工程

图搜索置于独立目录，提供自己的 CMake 和使用说明。可在不提供 SST/MQSim 源码、安装或构建缓存时配置、编译、运行；依赖的公共采集组件须显式提供，不通过模拟工程间接取得。

保留无插桩 benchmark、完整静态采集、独立 CPU 测量和必要功能核对。完整 IR 不抽样；诊断子集不能替代完整输入。保持现有 `ndpsim-ranked-expansion-v1`、SIFT1M/NSG、容器／计数、FP32 输入、固定维序 FP64 L2 与禁 fast-math/FMA 的参考语义。

功能算子实现作为可单独维护的模块供原生业务使用；采集接口不得要求用户调用模拟器 Runtime、SST 或 MQSim。

### FR-045-03 通用静态 IR 与采集接口

定义版本化、可校验的通用包契约，至少包含：

- 负载、采集构建、算子语义及输入内容的来源身份；内容身份可作为元数据保存，不要求模拟时重新打开原始 payload。
- 逻辑对象、大小／形状、切片／访问、输入输出端口及输出大小。
- 稳定操作 ID、请求／查询边界、工作量特征及单位。
- DATA、ADDRESS、CONTROL、ORDER 依赖、状态版本和终态。
- 完整性、索引、分片和结束标记；可追溯的采集／校验报告。

通用校验器不能内置图搜索固定循环语法。图搜索对象、操作及特定合法性由扩展描述和校验器提供。首版无需支持共享可变对象或任意跨查询语义，但须明确支持边界并拒绝非法引用。

静态拓扑和逻辑访问是执行输入，采集时戳不是调度输入。业务相关 Work 由采集侧产生并独立核对；模拟侧检查其类型、单位、范围、可推导关系和模型兼容性，不再宣称本次重算了真实 Work。包损坏、缺失、重复 ID、非法依赖、环、越界、未知算子或不完整终态须失败关闭。

### FR-045-04 算子扩展

用户可在独立扩展模块声明新算子的语义版本、输入输出、依赖约束、Work 特征及单位、大小计算规则和能力。功能实现与模拟描述分开：真实实现用于业务执行和采集；模拟描述用于校验和映射。

新增算子不应要求修改通用调度核心或 SST/MQSim。涉及当前后端未支持的硬件能力时，须显式扩展后端，不能仅注册算子就声明支持。提供一个完整的最小扩展示例。

### FR-045-05 映射与下沉接口

映射独立于功能算子和成本公式，描述给定放置下的读取、传输、缓冲、服务、返回及释放依赖。首版位置为 Host 和现有 Controller；提供现有 L2 的两种映射及声明式放置选择。

下沉必须改变实际模拟数据路径：Controller 本地读取向量，必要输入进入 Controller，结果返回 Host，禁止先把完整向量回传 Host 再声称近存计算。输出大小、容量分块、credit、消息及 Close 排空均由映射和资源契约约束。

支持相同语义 IR 比较不同合法映射；缺失映射、输出大小规则或硬件能力时拒绝执行，不默认回退 Host。物理分块变化所需的 Work 分解必须有显式规则；不可分解的采集 Work 不得按比例猜测。

### FR-045-06 外置 Layout 与 MQSim 配置

Layout 描述逻辑对象到 LBA extent 的映射、对齐、大小和命名空间约束，与业务内容和原始数据格式解耦。MQSim 仿真配置作为用户可编辑文件加载，不再通过修改源码或重编译平台才能切换设备参数。

用户在两次运行之间修改文件即可重新运行；本版不要求运行中热更新。启动时检查格式、单位、容量、范围、重叠、溢出及后端支持组合。不是所有 MQSim 配置都自动获得支持或精度承诺。

Layout、MQSim、资源、Profile 和放置配置的引用相对其声明文件解析，保存实际加载文件及完整有效配置快照和 hash。明确字段权威，避免同一带宽、容量或时延在多处隐式覆盖。配置改变后重新校验映射、初态和模型条件，不默默沿用旧结果。

### FR-045-07 独立 Cost model

模型输入为算子／阶段、位置、Work、必要上下文和硬件条件，输出明确单位的非负有限服务需求。模型不得包含资源等待时间；排队由调度与资源层负责。整数化、零服务和溢出处理须确定且可核验。

支持参数化模型和用户扩展模型；不要求修改核心调度才能增加公式。CPU、Controller 计算及独立缓冲等模型与 MQSim 已计费的存储／链路服务边界明确，一项资源或流量只有一个计费者。

每个模型声明语义／特征版本、训练或参数来源、范围、准备上下文及硬件适用条件。缺模型、特征不匹配或越界失败关闭。实验性假设可显式配置并标注，不伪装为校准模型。

### FR-045-08 独立测量与拟合工具

提供独立调用的 Measurement 校验、拟合、评估与 Profile 导出流程，无需启动或构建 SST/MQSim。输入不依赖固定本机路径或 V0.4 阶段脚本中的历史 manifest。

通用工具负责样本质量、特征声明、模型生成和报告；图搜索特定桶、特征及训练方案放在负载扩展。采样与完整 IR 分开，保留计时开销、低信号和采集扰动检查。互斥计费边界先冻结，不以 QPS 或墙钟残差补成本。

区分两类来源并逐阶段报告：预测模型与对应轨迹的逐调用实测表。后者可用于现行验收中的指定阶段，但不能计作模型泛化精度。表绑定操作键、Work、采集条件和包身份，缺项或失配拒绝。原生 benchmark 独立于制表运行。

训练 tuning32 与 evaluation128 按原始 query ID 隔离；评价数据不得回流拟合。评价后调整模型须新版本并披露已暴露结果，历史披露继续保留。

### FR-045-09 IR 复用与信任边界

保持业务语义、逻辑访问与 Work 不变时，可更换合法的物理 Layout、设备配置、资源配额、成本模型和算子放置，并重新进行兼容性校验。模型和实测表是否可复用还受各自条件限制。

输入、算法、数值精度、逻辑分块、分支、访问或 Work 改变时必须重新采集。对依赖时延的竞速／超时业务，以及改变结果精度的下沉，固定 IR 不能证明反事实性能，须明确 Unsupported。

哈希提供完整性和来源关联，不证明功能正确。图搜索由独立数值／搜索／Work 校验建立采集可信性；用户负载需提供相应功能验证。未经业务语义校验的包即使通过结构检查，也必须在报告中区分其验证等级。

### FR-045-10 统一用户入口与输出

提供单一用户 CLI 及少量职责清楚的子命令，覆盖校验、拟合、模拟、比较，以及图搜索采集的便捷调用。具体命名由实施阶段确定，文档不得把建议命令当成已实现接口。独立图搜索仍保留自身运行入口。

用户无需了解内部 Python 脚本调用链。内部模块可拆分；取消重复公开入口、历史阶段入口及隐式构建／验收副作用。构建、正常模拟和完整验证可分别执行。

输出至少包含有效配置、输入包与模型身份、命令和退出码、模拟时延／吞吐、各阶段服务及等待、逻辑与物理流量、资源峰值、排空状态及参数来源。采集的 top-k／摘要须标记为参考证据，不得标为模拟重新计算的结果。Unsupported 不填 0，条件预测不标为实机验证。

### FR-045-11 测试清理与迁移

移除仅证明旧引擎／旧默认／旧命令兼容的测试义务，不继承旧 12／52 配置数量作为本版门槛。按当前风险保留或迁移有效断言，尤其是事件顺序、依赖门控、布局分块、唯一计费、缓冲释放和失败关闭。

清理前列出保留、迁移、删除及理由；新路径通过对应出口后再删除旧实现。保留 V0.4 文档、发布证据及依赖身份的可追溯入口，不把归档等同于 V0.4.5 通过。发布包无需携带全部历史开发脚本和本机结果实体。

### FR-045-12 发布与扩展体验

提供安装／依赖说明、最小可运行例子、真实图搜索复现指南、IR 采集教程、新增算子与依赖教程、映射／下沉教程、cost model 与拟合教程、配置说明及结果解读。

从干净目录按文档可完成构建与最小工作流；数据不随包分发时，给出来源、准备步骤、身份和预算要求。完整验收不要求访问维护者私有历史目录。声明已验证 OS／架构，其他平台不得未经测试标为支持。

小型教学夹具必须展示“真实执行／采集 → 新算子与依赖 → 成本与映射 → Host／Controller 对比”，且不修改通用调度核心。它验证扩展接口，不构成第二负载精度承诺。

## 6. 验收标准

### 6.1 正式数据与精度口径

正式性能负载沿用完整 SIFT1M、锁定 NSG、原始查询切分 tuning32／evaluation128，以及 L/E=32/64、64/128 两点；不通过更换算法、查询或减少 base 达标。严格 CPU 精度限定记录条件下的单 worker Host 内存驻留，不能推广至任意机器。2/4 worker 保留资源正确性定向覆盖，性能仅作可选诊断，不继承旧版完整规模诊断矩阵为强制出口。

每个严格评价点至少三次独立原生 benchmark、两次模拟；比较窗口、分位数和接纳规则与现行标准一致。模型阶段误差中位数 ≤10%、P90 ≤20%；查询延迟 P50 误差 ≤15%、P95 ≤20%；批次 QPS 误差 ≤10%、CPU 总服务需求误差 ≤15%。实测表阶段单独验证覆盖、质量、身份和唯一计费，不进入预测模型精度结论。保留采集 A/B/A 扰动 ≤5% 的质量标准，重复日程在采集前冻结。

重构导致来源身份变化时，必须重新验证并按条件重新采集／拟合；不得编辑 hash 继承旧通过。正式运行前检查输入、RAM、磁盘、输出预算及超时，保留失败目录，在新目录重跑。

## 8. 风险、限制与后续决策

- 移除运行期功能重算后，错误的采集 Work 可能产生看似合理的时间。必须明确采集可信边界，不能仅靠包 hash 或最终 QPS 自证。
- 图搜索专用状态与通用调度可能仍有耦合。实施前需定向核查；以现有完整图搜索和小型教学扩展共同验证接口，不以目录移动证明解耦。
- 改变物理分块、准备上下文或放置可能使原 Profile 不再适用，须显式分解、重新测量或声明假设，不能自动套用。
- 当前精度包含绑定轨迹的实测阶段，不是所有算子的通用预测能力；报告须持续分列。
- SSD／PCIe／Controller 仍为 `configured_unvalidated`，MQSim 行为对拍不等于真实硬件校准。
- 目录布局、CLI 名称、配置格式细节、注册接口和测试数量在实施计划中确定；不能借此变更本文的职责边界、精度门槛或缩减完整查询覆盖。

本 PRD 的完成仅代表需求已正式记录，不代表新 schema、接口、工具、配置或运行命令已经可用。
