# M0.2 本机 macOS 环境与原生基线


当前平台常规构建已统一为根 CMake 默认自动构建 SST，见 [README](../README.md)。本文保留 M0.2 原生 oracle 的历史流程及证据，M0.2 脚本和它生成的 SST 安装不再是平台构建前置条件。
范围：完成 M0.1 之后的本机工具链、SST Core 原生构建与命令入口、未修改 MQSim 的受控读取。没有实现平台元素库、事件桥或 ANNS；元素模块加载属于 M1.1。验收记录见 [证据目录](evidence/m0.2/)。

`docs/evidence/` 是本机生成的验收产物，已被 Git 忽略，不随提交分发。本文和任务清单中的 evidence 链接指向本机记录；新检出可按下述命令在指定输出目录重新生成日志及 manifest。

## 工具链与构建

[deps.lock.json](../deps.lock.json) 锁定两个已初始化子模块的 URL、完整 commit、空补丁 SHA256，以及本机工具路径和版本。工具：Apple Clang 21.0.0（clang-2100.1.1.101）、libc++、C++17、Miniconda Python 3.13.12 和同前缀 `python3.13-config`、Autoconf 2.73、Automake 1.19、GNU Libtool 2.6.2、GNU m4 1.4.21、GNU Make 3.81、CMake 4.4.4。macOS 26.5.1 / arm64，SDK 26.5，部署目标 26.5；10 个 CPU、16 GiB 物理内存，构建并发 2。资源瞬时状态另存 `resources`、`vm-stat`、`disk-space` 日志。

本轮安装命令为 `HOMEBREW_NO_AUTO_UPDATE=1 /opt/homebrew/bin/brew install autoconf automake libtool`，必要依赖 GNU m4 同时安装。脚本不下载、不升级、不初始化子模块。工具缺失或版本漂移时明确失败；需要重新审查锁文件，不能自动跟随新版本。该锁是本机精确环境约束，不是跨机器通用安装器。

从仓库根目录执行，构建目录和输出目录必须尚不存在：

```sh
/opt/homebrew/Caskroom/miniconda/base/bin/python3.13 tools/macos_m0_2.py \
  --output results/m0.2-build
```

脚本使用当前子模块固定提交的 `git archive` 生成构建快照，记录 archive SHA256；不修改 SST/MQSim 的工作区。SST 在独立构建目录执行原生 `autogen.sh`、configure、make、install，关闭 MPI/HDF5/ncurses。MQSim 使用快照中原生 Makefile，仅显式覆盖 CC、LD、CC_FLAGS 为同一 arm64 Apple Clang/C++17 工具链；保留 `main.cpp`、原生事件循环、配置解析、FTL、缓存和 NVMe 路径，补丁为空。许可证随源码快照保留。

两项实际环境修复均在脚本环境中完成：直接调用 CLT 编译器必须显式设置 SDKROOT，否则链接器找不到 `libSystem`；Miniconda 的 config 给出的库路径不足，必须显式增加同前缀 `-L.../lib`，并为嵌入运行添加 rpath。未修改上游 Python 检查宏。

原生 MQSim 在该 Clang 下还存在退出兼容问题：`IO_Flow_Base` 是抽象类但析构非 virtual，Host_System 通过基类指针删除 flow；默认代码生成的完整析构入口是 `brk #1`，小读全部 serviced 后进程仍以 133 退出。仅为 MQSim 增加 `-Xclang -mconstructor-aliases`，使完整/基类析构入口使用同一地址；脚本通过符号表断言该选项生效，并要求最终进程退出 0。异常退出前后原生 XML 相同。**这只是保留原生源码的工具链兼容措施，不修复非虚析构造成的 C++ 未定义行为或资源释放缺陷**；不将其当作 M1.1 生命周期验收。后续正式适配仍需处理这些上游缺陷，并保留此固定构建的原生时序对照。

默认安装后的命令入口：

```sh
build/native-macos/install/sst/bin/sst --version
build/native-macos/install/sst/bin/sst --usage
build/native-macos/install/sst/bin/sst --help=timebase
build/native-macos/install/sst/bin/sst-config --CXX
```

重复验收已有构建，另选一个不存在的输出目录：

```sh
/opt/homebrew/Caskroom/miniconda/base/bin/python3.13 tools/macos_m0_2.py \
  --verify-only --output results/m0.2-repeat
```

干净复建可另传 `--build-root build/m0.2-rebuild`。脚本不删除或覆盖旧结果。MQSim 现在直接在子模块工作区开发；原生工具允许其有修改，但始终从锁定原生 commit 独立归档构建 oracle，不使用已修改的工作区，详见 [源码维护约定](mqsim-source-management.md)。版本、源码、gitlink、二进制和构建回执被核对；不将已有不同工具链的二进制作为当前基线。

## 输入、设备与初态

[SSD 配置](../configs/native/ssdconfig.xml) 由固定版本的原生 `ssdconfig.xml` 缩小而来，原文件保留不动。2 channel × 1 chip × 2 die × 1 plane × 64 block × 64 page × 4096 B = 64 MiB 原始 NAND；512 B sector；NVMe，QD 容量 16、fetch 1；SIMPLE 数据缓存管理器、flow 缓存 TURNED_OFF；CMT 64 KiB、非 ideal mapping；设备 seed 321。其他延迟、带宽、GC、wear leveling 等参数继承原生配置，全部属于 **configured_unvalidated**，未对真实 SSD 校准。

每次启动新进程，原生 main 调用 Reset；预处理关闭，初始占用设置 0，没有提前写入或 warmup。首次 READ 沿原生 `online_create_entry_for_reads` 懒建立映射；保留 CMT 和原生内部维护。这里只记录原生配置初态及进程隔离，没有实现确定性预装载、映射摘要导出或测量窗口切换（这些属于 M1.3）。只读 trace 不等同于 NAND 功能内容验证。

[trace](../configs/native/reads.trace) 每行格式为 `arrival_ns device_id start_LBA sector_count op`，READ=1，WRITE=0，单次 replay、100% 执行。4 个请求在 1/2/3/4 ms 到达，LBA/sector 数为 `(0,8)`、`(8,8)`、`(7,2)`、`(32,8)`；合计 26 sectors = 13312 B。第三个请求跨 4096 B 页边界；本轮核对请求完成与读字节量，不宣称已核对内部事务级拆分时序。到达间隔用于隔离小读；设备配置中的 QD 16 不代表负载同时发出 16 个请求。

脚本将输入复制到各自运行目录，执行：

```sh
/absolute/build/root/src/MQSim/MQSim -i ssdconfig.xml -w workload.xml < /dev/null
```

MQSim 原生末尾仍打印 `Press any key`；EOF 令原生 `cin.get()` 返回，无须补丁。输入文件预先存在；每次设置 60 秒超时，超时杀死整组进程并记录失败。未改造上游的交互错误处理能力。

## 验收口径与限制

每次验收启动两个新 MQSim 进程，断言生成和 serviced 均为 4、读取 13312 B、写请求和写字节均为 0、完成延迟为正、两份完整原生 XML 的 SHA256 完全一致。SST 检查 version/help/config 命令、arm64 二进制和动态链接；另编译运行 C++17/Python 嵌入探针，并用 CMake 4 读取 SST 导出的 imported targets。CMake 探针没有创建或加载元素模块。

完整 argv（含 `/usr/bin/time -l`）、cwd、显式环境、stdin、超时、退出码、stdout/stderr 路径及 SHA256、墙钟秒数和 Darwin maximum RSS 字节记录在每次 manifest。RSS 是 time(1) 对该命令的报告，构建并发进程的瞬时总内存不由该数值保证；不把 `peak memory footprint` 混作 RSS。墙钟与 RSS 衡量仿真器执行开销，不作为模拟 NAND 时延。原生 XML 的 response/delay 经过上游 getter 按微秒输出，不能据此声称已经获得逐请求整数 ns 完成轨迹。

本轮不运行 E1～E5 或 AC-01～AC-11；尤其没有原生/桥接对照，不能标记 AC-08 通过。不承诺其他 Python、SDK、CPU 架构、MPI/HDF5、原生大几何或元素 ABI 已验证。不自动推进 M1.1。
