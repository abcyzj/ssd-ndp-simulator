## 顺序、依赖与关闭规则

实施顺序为：V04-0 → M1 独立程序/参考语义 → M2 静态包契约/采集 → M3 Profile/静态执行/内存路径 → M4 全量评价采集与分层验证 → M5 下沉/交付。依赖表示所需的具体产物，不把前一阶段所有精度出口作为后续所有工作的门槛：

- V04-2a 可与 M1 核心开发交错；V04-3a、3c、3d 和 4a 可在契约冻结后用合成夹具开发，不等待拟合精度达标。
- V04-3b 先冻结训练侧模型；V04-4b 分别核验实测查表阶段和其余模型阶段的预测误差。此拆分共同满足 PRD 的 M3/AC-04-04 出口，评价误差使用 evaluation128 样本。
- V04-1c 先核对 native/direct/旧动态ir，避免把未实现的静态执行器变成采集的循环前置依赖；2b 提供完整包采集/校验，3c 用夹具及训练包开发，4c 补齐正式两点静态执行语义。评价包在3b冻结模型后采集，不能回流拟合。
- V04-5b 在每次相关改动后增量回归；V04-5a 的配置/账本/扫描框架可先做，CPU 精度未达时仅能产出探索报告。V04-5c 必须汇总全部必需出口。

未完成任务的“完成证据”列为**待产出**，已关闭任务填写实际证据。关闭时填写实际路径、运行日期、输入/配置/源码与依赖/构建身份、命令、退出码、日志、逐项断言和产物 SHA256；失败与重跑分目录保留。默认根目录 `results/v0.4/<task>/<new-run>/`，下列文件名是实施建议，不是已存在的工具接口。统计、详细、训练、评价、兼容回归证据分别标注用途；大输入和运行产物不入 Git。
