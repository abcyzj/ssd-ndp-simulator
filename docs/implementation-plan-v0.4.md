# V0.4 可执行任务清单

日期：2026-11-03（Asia/Shanghai）。**18项任务中，V04-0开工冻结已完成，其余17项待实施；未执行V0.4功能或精度验收。**当前可运行交付仍为 [V0.3](releases/v0.3.md)。开工证据与实际检查见[冻结记录](start-freeze-v0.4.md)。

需求权威为 [V0.4 PRD](prd-v0.4.md)；表中 N/P/C/S/V/O 编号均为该 PRD 的 `FR-04-` 需求（如 N01 为 FR-04-N01）。源码核查的版本、来源、定向复核与证据局限见 [复核记录](source-audit-v0.4.md)。执行阶段按实际产物更新本清单，历史通过、接口设计或本页文件名均不代表实现完成。

## 验收配置数量

按 [14配置验收矩阵](validation-matrix-v0.4.md) 执行：A01～A04单线程CPU4个、D01/D02多worker诊断2个、R01～R04旧默认兼容4个、O01～O04下沉参照/扫描4个。**14指模拟参数配置，不是运行总次数**；原生重复、模拟确定性复跑、训练、A/B/A、detail8、smoke和定向/继承测试另计。V0.3完整52条及配套效率/Q梯度改为按需深度回归，触发条件和记录要求以该矩阵为准，不修改旧工具的完整性定义。各阶段按受影响子集推进，最终V0.4交付覆盖全部14配置及规定的配套证据。

## 顺序、依赖与关闭规则

实施顺序为：V04-0 → M1 独立程序/语义 → M2 采集 → M3 Profile/内存路径 → M4 分层验证 → M5 下沉/交付。依赖表示所需的具体产物，不把前一阶段所有精度出口作为后续所有工作的门槛：

- V04-2a 可与 M1 核心开发交错；V04-3a、3c、3d 和 4a 可在契约冻结后用合成夹具开发，不等待拟合精度达标。
- V04-3b 先冻结训练侧模型；V04-4b 才以独立评价数据关闭 Level A。此拆分共同满足 PRD 的 M3/AC-04-04 出口，不把训练内误差当独立验证。
- V04-5b 在每次相关改动后增量回归；V04-5a 的配置/账本/扫描框架可先做，CPU 精度未达时仅能产出探索报告。V04-5c 必须汇总全部必需出口。

未完成任务的“完成证据”列为**待产出**，已关闭任务填写实际证据。关闭时填写实际路径、运行日期、输入/配置/源码与依赖/构建身份、命令、退出码、日志、逐项断言和产物 SHA256；失败与重跑分目录保留。默认根目录 `results/v0.4/<task>/<new-run>/`，下列文件名是实施建议，不是已存在的工具接口。统计、详细、训练、评价、兼容回归证据分别标注用途；大输入和运行产物不入 Git。

## 可采用的实现默认

以下均为建议默认；实现者可在编码/采集前记录理由和影响后调整，不需为命名、布局等细节停下询问。PRD 确定约束和精度门槛不能用默认决策覆盖。

| 事项 | 建议默认 | 边界 / 验证责任 |
| --- | --- | --- |
| 模块与根构建 | C++17纯核心、native runner、现有IR适配；根选项建议 `NDPSIM_NATIVE_ONLY=ON`，native目标建议 `ndpsim_native`；在SST准备前分支 | 独立核心不包含模拟依赖；需要JSON时使用可独立获得的头/解析层，不让native仅为JSON而依赖SST子模块；不改direct冻结算法 |
| 显式配置 | 建议 `data_provider=ssd\|host_memory`、`cpu_profile=<path>`、`native_workers`；省略均走现有SSD/成本，`content_backend`仍只指宿主功能字节后端 | 校准内存组合先限IR+Host；不支持组合直接拒绝；manifest记录有效值与模型hash，现有engine默认ir不变 |
| 完整评分计时 | 真实搜索中“按ID取本批数据→准备→L2→产生packed得分”为审计外层；内部互斥分为取数/准备和现有squared_l2整体，后者已含decode/分配/检查/编码 | 外层总时间仅作闭合审计；模型只用互斥子阶段之和；不另建纯算术/精细Cache模型；其他控制及初始化/结束单独归属 |
| 内存与SSD成本迁移 | A计真实内存取数准备；B/C由存储负责提供字节，只保留各自实际发生的CPU阶段；模型记录 `preparation_context` 等条件 | 不剥掉原函数内部实际decode再重复计费；A随机取数和SSD返回缓冲不能默认等价。可在训练侧采返回缓冲条件，或明确标假设做敏感性预测；身份/range仍须合法，不得绕过失败关闭 |
| 时钟与短算子 | 单调墙钟+线程CPU时钟；训练侧测空计时开销和分辨率，极短调用抽样/批量测量；保留raw/corrected/质量标记 | 负修正量标低质量，不钳成0再用于拟合；训练冻结主要/短算子分类、闭合与未归因规则。建议主要阶段未归因≤5%作为采集质量目标，短阶段用绝对阈值；这是待2a/训练预检冻结的建议，不是PRD新增精度AC |
| worker、并发与slots | 单线程1/1/1；诊断2/4 worker、CPU slots同worker，查询接纳上限32；接纳后等待worker，worker占有整查询直至完成；同worker chunk串行 | admission为进入有界查询队列，worker开始另记；latency含接纳后的worker等待，offered wait在队列外。native/sim用同一时间线/固定领取顺序；全部请求起点可供给，不能混成原生并发2与模拟并发32 |
| 稳定语义关联 | 原始query ID + iteration/semantic_batch + op/stage + 有序ID/chunk索引；关联到本次IR/task，不比较数值task ID相等 | 时戳/耗时只在Measurement，语义Trace不驱动模拟；依赖及输出摘要照常核对 |
| 模型拟合与舍入 | 锁定Python训练工具；常数、非负约束线性、训练范围内分段表，训练内选型；非负有限估计向上取整整数ns，检查uint64溢出 | 同一Profile/Work确定性；不向上取整成强制最少1ns；零服务仍异步；未知/超范围无默认回退 |
| 采集与预算 | 线程本地有界buffer、统计模式不留全历史；detail仅detail8；训练采样起点可用1/16并记录权重/覆盖，不足由训练侧补充 | 正式采集前冻结采样率/输出预算；起点建议沿用SIFT阶段RSS上限（查询4GiB、后处理512MiB）、查询每点7200s/后处理600s、卷余量≥20GiB；V0.4聚合磁盘建议独立上限25GiB，先量Trace再冻结，不能直接挪用旧15/25GiB证据口径 |
| 下沉扫描与报告 | 先用现有Controller基准算力的0.5×/1×/2×（以合法显式参数表达）做双向扫描，其余固定；每点保存，不只选最快 | 扫描范围在运行前冻结；CPU/SSD/PCIe/Controller分别标来源；只有指定Mac和条件的CPU精度可被验证，SSD/PCIe/Controller继续 `configured_unvalidated` |

本计划不扩展负载、硬件位置或精细内存/存储模型，不要求原生异步SSD搜索，不修改SST Core，不引入MQSim patch栈，不自动提交、推送或升级/初始化Git。V0.3完整交付状态保留在历史记录，不能移作V0.4已完成证据。
