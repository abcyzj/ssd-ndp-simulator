## 1. 产品目标与使用者

面向存储架构研究者，将当前小型合成数据闭环仿真扩展为可在真实 ANNS benchmark 上重复开展实验的平台。本版交付数据集为 SIFT1M，使用真实向量、查询、图索引和匹配的 ground truth，比较主机与 SSD 控制器侧距离计算的搜索质量、模拟性能及数据搬运差异。

V0.2 应能回答：

- 在相同数据、图索引、搜索参数和数值语义下，改变距离计算位置会怎样影响模拟时延、吞吐、PCIe 流量及资源等待？
- 随搜索质量目标变化，主机与盘控方案的 Recall—性能曲线如何变化？
- 真实数据的维度、图结构和搜索访问行为使瓶颈落在哪里？
- 平台能否以明确的内存和墙钟成本完成百万向量规模的实验？

真实 benchmark 提高负载代表性，不自动证明硬件模型已校准。平台不以提出新 ANNS 算法、实现生产级数据库或保证盘控更快为目标。

## 2. 需求确定程度与版本范围

沿用 V0.1 的需求标签：

- **确定约束**：本轮目标或必须继承的正确性边界，规划不得弱化。
- **建议默认**：为形成可交付版本而建议采用，可在规划中说明理由、替代方案及影响后调整。
- **待核实**：需要代码核查、原型或资源测量后决定；不能据此声称已有能力。

### 2.2 明确不作为本版前置条件

- 完整 DiskANN/AISAQ 复现、PQ/IVF、多层图、过滤检索或多距离度量。
- 搜索控制流迁入 SSD、其他近存计算位置、多 SSD、多主机。
- 在线索引更新、崩溃恢复、任意在途取消与故障恢复。
- 精细共享 DRAM、周期精确计算、完整 CPU cache 或操作系统模型。
- 十亿级全量数据、生产级在线流量系统、Web 界面。
- 必须依赖真实 GPU 的准备或执行流程。
- 全部硬件参数的实测校准和绝对硬件性能准确性承诺。

导入某算法构建的图不等于复现该算法完整搜索。若选择加入上述能力，规划必须单独说明新增需求、成本、计费变化和验证范围。

## 3. 当前基线与增量差异

以下为讨论时的静态核查结果，不代表已运行大规模实验；实施前须核对当前代码。

| V0.1 当前行为 | V0.2 缺口与影响 |
| --- | --- |
| 内部 FP32/固定槽邻接格式，支持 `--data` | 缺少标准 benchmark 导入、来源与子集身份管理 |
| 环边加随机邻居的测试图 | 缺少真实离线建图及索引身份，不能据此评价真实索引负载 |
| Python 全量解码、逐查询穷举并完整排序生成真值 | 百万规模的内存和计算成本不可直接沿用 |
| C++ 全量文件与逐对象字节、元数据存储 | 需要减少内容副本和大量小对象开销 |
| 仅 `native-small`，部分拓扑硬编码 | 容量不足，配置与实际拓扑必须统一 |
| 向量、邻接分别按 512 B 对齐 | 对齐放大会影响容量、读取与比较结论 |
| 测量前模拟写入整个布局并排空 | 大规模初始化成本待测，不能无验证跳过 |
| 关闭 JSONL 后仍保留多类内部记录 | 需控制随事件和查询总数增长的内存 |
| 所有查询同时 offered，有限并发接纳 | 属于批量负载，不等价于在线到达流量 |

容量示例：按现有布局、最大度数 R=64，SIFT1M（128 维）向量与邻接合计约 1.024 GB，为十进制且未计 SSD 预留空间。当前 XML 的原始 NAND 数据容量约 64 MiB，实际 namespace 还受配置影响。这是静态容量估算，不是 RSS、索引构建内存或性能实测。

## 4. 关键用户流程

1. 用户取得指定版本的原始 benchmark，校验来源、文件哈希和使用条件。
2. 导入并验证 base/query/learn，选择完整 base 或显式子集，生成规范化数据及 ID 映射。
3. 离线构建并导出真实图索引、入口和构建记录。
4. 导入匹配的官方真值，或独立计算所选 base/query 的精确真值。
5. 选择设备 profile、搜索参数、计算与缓冲配置，执行容量和资源预检查。
6. 对同一份输入分别运行 host/controller，输出结果、质量、模拟性能与流量。
7. 扫描搜索参数，生成质量—性能比较；复用已完成的数据准备产物。
8. 保存配置、版本、身份、命令、退出码、断言和模型限制，支持复跑。

## 5. 必须满足的功能需求

### FR-02-01：标准数据导入与身份管理

- 支持选定 SIFT1M 版本的 fvecs/ivecs。既有 fbin/ibin 通用导入及错误夹具继续保留，但不要求完成 Deep10M 数据集适配。
- 校验头部、维度、数量、类型、字节序、长度、截断、有限数值及 ID 范围；错误输入应在仿真前拒绝。
- 区分 base、query、learn；不得将查询集作为无声明的建图训练或调参数据。
- 记录来源、原始与转换后哈希、转换器版本、度量、预处理、子集规则和 ID 映射；不隐式归一化、改精度或重排 ID。
- 支持固定 seed 或显式 ID 列表的查询选择，并记录顺序及覆盖数量。
- 大文件采用分块校验和增量哈希，不要求全部展开为 Python 浮点对象；已准备数据可复用。

### FR-02-02：真实图索引准备

- 接入至少一种离线真实建图方式，并支持导出仿真所需邻接、入口和节点映射。
- 记录构建器完整版本/commit、依赖、参数、seed、线程设置、输入与输出哈希；不假定多线程建图天然逐位确定。
- 验证节点覆盖、degree/ID 边界、入口有效性，报告度数分布及可达性检查结果；不得静默截断超出固定槽容量的邻接。
- 建图的墙钟、资源成本与模拟查询性能分开；索引构建无需进入 SST 查询时间线。
- 原有随机图夹具保留；真实 benchmark 实验不得以随机图冒充真实索引。
- 外部工具的支持平台、许可证、构建入口和版本锁定必须明确，不依赖浮动的“最新版本”。

### FR-02-03：搜索语义与两放置一致性

- 明确实际搜索策略名称、入口、候选结构、批次、去重、扩展预算和终止条件。
- 两放置使用相同数据、图、搜索参数、查询顺序和数值语义；同一查询的结果不因资源完成先后而被无声明地改变。
- 保留真实结果驱动访问、异步 continuation、服务和必要传输完成后可见等现行契约。
- 不允许离线预跑完整访问 trace 替代正式闭环实验。
- 如果修改候选算法或数据结构改变了控制工作量，应同步计费说明与回归，不能仅以真实墙钟优化为理由遗漏模拟成本。
- 复现命名算法时另需参考实现功能对照；复用其图但采用项目自有搜索时，必须明确标注。

### FR-02-04：真值与质量评估

- 支持导入官方精确近邻 ID；支持为无匹配真值的 base/query 生成独立真值，不以近似搜索结果充当真值。
- 真值绑定 base/query 身份、ID 映射、度量、k 或最大可用 K、生成方法和数值/同分规则。可从 K≥k 的真值提取前 k，校验规则需版本化。
- 仅抽样 query 时按原 query ID 选行；更换或缩小 base 时使用匹配真值或重新计算。不得从完整 base 真值简单过滤 ID 得到子集真值。
- 官方文件仅含 ID 时允许距离缺省，不填伪造距离。模拟输出仍保留真实 top-k 距离。
- 保留小规模固定维序 FP64 oracle；大规模可采用分块或加速的独立精确检索，但必须说明累加精度、并列处理及与内部语义的差异，并做小规模交叉核对。
- 分别定义集合交集 Recall@k 与 1-recall@R；输出不能混用名称。结果不足 k 时明确状态，集合 Recall 分母仍为 k。
- 无法由有限官方 top-K 判定的并列边界应注明或补算，不静默宣称符合内部严格 ID 排序。

### FR-02-05：大规模功能内容与状态管理

- 支持选定完整 base 的内容访问，避免强制全量 Python 对象展开和不必要的 C++ 内容副本。
- 建议采用文件映射/分块内容后端与紧凑元数据；具体实现由规划确定。
- 真实宿主文件缓存与模拟主机/盘控驻留必须分开；mmap 不授予算法免费访问或模拟缓存命中。
- 已完成任务、句柄和查询状态及时回收；保留必要的在途关联、可见性和生命周期验证。
- 规划时分别估算导入、建图、真值、初始化、查询和后处理的内存及磁盘峰值；制定基线机器上的资源预算。
- 支持明确诊断容量不足和不支持的规模，不以 OOM 或长时间无进展作为正常错误处理。

### FR-02-06：设备 profile、布局与资源容量

- 提供能够承载目标布局的设备 profile，保留 native-small 回归配置。
- 配置必须一致驱动设备几何、分区拓扑、namespace 和记录产物；不强制本版支持任意外部 XML 热切换。
- 启动前检查布局末地址、实际可用容量、地址/字节溢出和控制器最小可前进工作块。
- 按真实 d、chunk、scratch、查询常驻量和并发数验证盘控缓冲；不直接沿用小数据默认值并假定有效。
- 明确逻辑有效字节、布局占用、sector 读取、NAND 与 PCIe 流量的区别，继续保持唯一计费者。
- 首阶段建议保留独立对齐布局。若增加紧凑布局或共置布局，需版本化、更新所有映射与核对器，并作为显式实验变量。
- 覆盖跨 sector/page 对象、拆分读取及服务完成前不可见等边界。

### FR-02-07：初始化与测量边界

- 首先保留确定性全布局预装载作为基准，分别报告初始化与查询测量成本及状态。
- 必须测量完整目标布局的预装载可行性；初始化不计入查询窗口，但其留下的 FTL/CMT/cache 状态必须明确。
- 快速初始化或状态恢复为条件性优化，不是无条件交付项；采用时需说明保存/恢复范围，并与基准核对映射、空闲空间及后续受控 I/O 行为。
- 不得未经验证跳过写入或重置 MQSim 时间，再声称初态等价。

### FR-02-08：规模化观测与输出

- 提供默认统计模式和可选详细诊断模式。关闭详细日志时，历史逐事件记录不应成为随事件总数无界增长的主要内存来源。
- 采用在线聚合、流式输出或等价方法，保持请求关联、channel/die 区间并集和生命周期统计的既有语义。
- 完整逐批对照可用于小夹具及固定查询子集；大规模运行至少保存逐查询结果及可复核的决策摘要，必要时重跑详细日志定位。
- 日志模式不能改变搜索结果和模拟性能；统计一致性需在可独立核对的小样本上验证。
- 记录各阶段实际墙钟和目标平台上可取得的 peak RSS，说明进程范围、单位和采集方法；无法取得时明确 Unsupported。
- 模拟 ns/QPS 与仿真器墙钟吞吐分开，不能相互替代。

### FR-02-09：可复现实验与公平比较

- 数据导入、建图、真值准备和仿真可独立执行、失败重试及复用；复用基于输入/参数身份，不仅依赖目录存在。
- 提供固定配置两放置对照，以及搜索参数扫描；输出 Recall—模拟时延/吞吐数据和可阅读的比较结果。
- 固定配置比较必须保持非放置因素一致；质量匹配比较须报告实际 Recall、搜索参数和未匹配点，不能只比较最快的一组。
- 调参查询和最终评价查询应明确区分；若使用同一集合，必须声明为探索性实验。
- 记录 offered、接纳、结果可见及排空口径。默认沿用批量负载，新增在线到达模型不是前置条件。
- 完整 base 加查询子集可用于规模验收，但需记录 subset、样本量和选择规则，不能称为全查询集 benchmark；小样本 p99 不得包装成稳定尾延迟。
- 配置、输入、索引、真值、源码、依赖、初态与产物身份完整；参数未校准时继续标记 configured_unvalidated。

## 6. 最小结果集与评价口径

| 类别 | 最低输出 |
| --- | --- |
| 实验身份 | dataset/index/truth ID 与哈希、base/query 规模、原始查询 ID、子集及预处理规则 |
| 搜索配置 | 算法语义版本、建图参数、入口、k/L/B/E/chunk 或对应参数 |
| 质量 | 每查询 top-k/距离/状态、明确命名的质量指标、样本量、真值定义 |
| 模拟性能 | 每查询接纳后时延、接纳等待、offered 时延、分位数、测量窗口及 QPS |
| 算法工作量 | 扩展节点、评分向量、候选控制工作量 |
| 数据与资源 | 普通/本地读取、各层字节量、H2D/D2H、计算服务/等待、缓冲峰值、支持的 channel/die 统计 |
| 准备与效率 | 导入/建图/真值/初始化/查询/后处理墙钟，RSS 或 Unsupported，磁盘占用 |
| 解释限制 | 设备初态、模型简化、参数来源、未校准项、不支持能力 |

资源累计忙时/等待不能直接相加当端到端延迟。不得以更低 Recall 换来的时延下降直接声称近存架构收益，也不设定“盘控必须更快”门槛。

## 7. 验收标准

使用独立编号，避免与 V0.1 AC 混淆。每项证据保存输入、配置、命令、退出码、输出、断言和哈希；静态检查、原型、quick subset、完整 AC 与规模实验分别标记。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-02-01 | 导入正确性 | 小型格式夹具覆盖头部、截断、维度、非有限值、ID 越界；合法转换保留数值和 ID，非法输入被明确拒绝 |
| AC-02-02 | 数据及真值身份 | 错误 base/query/映射/度量被拒绝；query 子集正确选行；base 子集使用重算或匹配真值 |
| AC-02-03 | 真实图可用 | 至少一种锁定建图流程产出有效邻接、入口、映射和统计；同一产物可供两放置复用；不得只交付随机图 |
| AC-02-04 | 数值与质量口径 | 独立小规模 oracle 核对距离/结果；官方 ID 真值可用；并列、k/K、不足 k、集合 Recall 与 1-recall 的夹具通过 |
| AC-02-05 | 闭环与放置一致 | 受控内容变化改变后续访问；两放置逐查询 top-k 一致、距离满足声明容差；固定小样本逐批决策一致 |
| AC-02-06 | 资源与布局 | 大 profile 容量正确，越界启动失败；跨页读取正确；真实维度与并发下不超 credit，盘控完整向量 D2H 为零且其他必要流量完整 |
| AC-02-07 | 初始化可信 | 基准预装载排空后才开始测量；若新增快路径，须通过已声明范围的初态及受控 I/O 对照 |
| AC-02-08 | 观测与内存 | 统计/详细模式结果和模拟统计一致；固定 base、并发下增加查询数的实验显示历史事件不导致线性内存堆积，保留结果的必要存储另行说明 |
| AC-02-09 | SIFT1M 规模运行 | 完整 1M base、真实图和固定查询集完成两放置运行及质量—性能扫描；满足规划阶段确定的资源预算，明确查询覆盖范围 |
| AC-02-10 | 已取消（原 Deep10M 规模运行） | 2026-10-31 移出 V0.2；汇总标记 N/A（范围取消），不计通过、不阻塞交付，保留编号以追溯 |
| AC-02-11 | 复现与结论边界 | 复用产物并重复固定实验，结果在声明规则内稳定；报告区分质量、模拟性能与仿真效率，不宣称未校准绝对性能 |

规模验收的查询数量、参数扫描点、可接受墙钟/RSS/磁盘上限和图质量检查标准必须在实施计划中确定，不能完成后按结果倒填。未执行规模验收不得宣称相应数据集已完整支持；若资源不足，记录阻塞与范围调整建议。

## 9. 技术核查与阶段出口必须解决的问题

1. 锁定 SIFT1M 的来源、文件身份、ID 规则和匹配真值。
2. 选择一种建图实现并核实 macOS/arm64 可用性、内存、构建成本、导出格式及许可证；说明为何适配当前接口。
3. 决定复用现有搜索还是实现命名算法；若改变搜索/控制成本，给出行为与计费差异。
4. 选择版本化数据、索引、真值 schema，并明确旧格式、旧配置和旧回归的兼容策略。
5. 实测小规模资源增长，估算目标规模的峰值；确定资源预算与查询抽样/扫描矩阵。
6. 核查设备 profile、硬编码拓扑、容量与预装载成本；判断是否需要快初始化，并定义其证明范围。
7. 明确 mmap/元数据/观测回收的实现边界，证明不会绕过驻留和可见性契约。
8. 将 FR、代码模块、里程碑及 AC 建立对应关系；列出风险、技术决策与未决项，不将实现建议直接当作已批准架构。

现有 [实施计划](v0.2-implementation-plan.md) 已给出架构起点与任务分解；上述核查项按阶段补充实证，无需重新开始整轮规划。实施记录应包含任务依赖、每阶段可运行产物、验证命令与证据位置，以及新需求相对现行文档/代码/测试的冲突处理。不得自动提交、推送、升级或初始化依赖；MQSim 若需修改，遵循原位开发、原生 oracle 和源码身份约定，SST Core 不修改。
