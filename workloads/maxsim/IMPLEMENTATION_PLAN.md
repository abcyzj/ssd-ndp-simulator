# MaxSim 语义 IR 生成器首批实施计划

状态：首批生成器验收通过（2026-11-19）。使用方法见 [生成器 README](README.md#生成与复检)。范围依据 [MaxSim 实验方案](../../docs/MaxSim_ndp.md) §2～§8、§10，以及 [V0.4.5 IR 契约](../../docs/contract-v0.4.5.md) 和 [采集 SDK](../../docs/capture-sdk-v0.4.5.md)。

## 交付目标

在 `workloads/maxsim/` 提供独立的 Python 负载生成入口。输入一份实验配置，输出相同配置和种子下可复现的候选序列、逻辑布局、`ndpsim-static-ir/2` 包与核验报告。负载从查询向量及候选 ID 已就绪开始，到 Top-K 描述及完成令牌为止。仅生成形状、地址、Work 和依赖元数据。首批验收落在生成与校验，三条路径的 SSD 执行、硬件配置选型、并发调度与性能测量属于后续接入。

## 参数归属

| 文档参数 | 首批处理 |
| --- | --- |
| 模型、`D`、`Nd`、模板 token 增量、`Nq`、`C`、`K`、文档 FP16/FP32、查询分量字节数 | 固化 ColQwen3 主配置与 ColQwen2.5、ColPali 的成对维度和长度预设。展开形状、有效字节、点积 FLOP、输出大小。文档 `storage_dtype` 与分量字节数联动，查询类型独立。保留模型引用、可用 revision 和精排 HNSW 背景字段。 |
| 文档总数、均匀/Zipf、指数、查询内去重、候选顺序、热度置换、种子 | 生成候选和逻辑地址。分别使用 `layout_seed`、`candidate_seed`、`arrival_seed`，记录采样算法和版本。按 `p(r) ∝ r^-α` 顺序加权无放回，保持抽样顺序。同组实验复用候选和布局。 |
| 文档对齐、逻辑读粒度、排序选项 | 使用受支持的连续、4 KiB 对齐、不按 LBA 排序的语义，支持 4/16/64/128 KiB 粒度。生成有效切片与尾部补齐后的逻辑请求账本。 |
| `host`、`host_compute_free`、`device_all`，算力、固定开销、协议、带宽 | 一份 IR 供三个方案引用。保存各方案的声明、单位和参数来源，派生查询下发和结果返回的有效载荷字节。保存 MQSim XML 引用、哈希和后端身份字段，缺失时明确标记待提供。7/14/28 GB/s 保留为有效载荷目标，100 GB/s 保留为解析参考。实际 PCIe 配置由后续接入确定。 |
| Host 缓存容量和 LRU、回填、预热、读窗口、全局 QD、暂存、批大小、重叠、引擎数 | 校验并保存为执行参数。IR 固定候选、读需求及数据依赖。实际命中、批次成员、反压和启动次数由后续执行时序决定。 |
| 开放泊松、封闭并发、查询数及 E0～E5 扫描 | 开放组用独立随机流产出到达时刻。封闭组保存并发度、候选顺序和完成后补发规则。提交主配置和分阶段扫描清单，以配置校验和派生量核验作为扫描交付。E6 可选扩展留到后续。 |

## 实施顺序

### 1. 配置与派生量

- 提供有效配置和参数来源，区分公开依据、仿真假设、继承项和派生值。区分实验建议测量查询数与本次生成的查询数，默认示例使用少量查询并保留主配置的语料逻辑规模。
- 对未知字段、未支持的模式、非法数值及字段组合失败关闭。检查 `1 ≤ K ≤ C ≤ corpus_documents`、形状和 dtype、对齐和 I/O 粒度、扫描阈值及 uint64 派生值。FP32 文档仍可配独立的 FP16 查询。
- 在编码之前报告候选条目、读切片、包、SQLite 临时索引和磁盘预算。用小规模生成量验证全尺寸配置。10,000 查询点如超过 SDK 部署预算，报告缺口并保留原配置和已有证据。

### 2. 候选和逻辑布局

- 冻结各随机流的种子和复现规则。为热度排名到文档 ID 生成固定置换。验证布局流、候选流、到达流互不消耗随机状态。开放到达序列保留整数 ns 转换规则与相同时刻的次序。
- 用一个只读语料逻辑对象表示文档槽位。`doc_bytes = Nd_effective × D × storage_component_bytes`，`stride = align_up(doc_bytes, 4096)`，偏移为 `doc_id × stride`。每个 IR 访问只覆盖有效字节。候选与读计划记录文档 ID、候选序号、原始访问切片和尾部补齐后的请求长度，填充只进入存储账本。
- 输出逻辑布局和最小 namespace 容量。提供了明确的页几何和容量时，可导出匹配对象目录的 `ndpsim-layout/1` 并检查范围与对齐。超出已给设备容量的配置保留派生容量报告，拒绝把地址取模或标成可运行布局。设备预装载状态由后续执行接入处理。

### 3. 算子声明与语义 IR

- 在负载目录维护版本化算子注册表和纯元数据大小规则。表达查询已就绪、候选的逻辑读取、逐文档 MaxSim、候选分数汇合与 Host Top-K 终态。每个文档评分依赖查询和该文档全部有效切片就绪，查询终态依赖所有候选分数。候选序号和稳定 stage key 用于核验提交顺序；只有真实语义依赖进入 DAG，避免为保持候选顺序把各文档评分串行化。
- 每个文档记录 `2 × Nq × Nd_effective × D` 点积 FLOP、有效输入和输出的 Work。MaxSim 输出为文档 ID 加分数，Top-K 输出含 `K` 条记录。保留逻辑访问到候选的关联供后续按文档重组批次。
- 复用 [`OperatorRegistry`、`PackageWriter` 和 `validate_package`](../../python/README.md)。可变输出大小使用负载内、绑定实现哈希的纯元数据规则，复检入口显式使用同一注册表。标记 `synthetic-fixture`、`split=fixture`，显式启用 fixture 校验。包内使用 SDK 四件套，其余产物放在包目录外。
- 单次生成产出展开配置、注册表、候选序列、布局及逻辑请求账本、IR 包、结构校验报告、独立账本核验报告和 E0～E5 扫描定义。记录生成器和仓库身份、种子、算法版本、输入和产物哈希。输出目录采用新路径，失败不得留下成功标记。

### 4. 首批验收

- **主配置账本**。以 `D=320`、`Nd=1024`、`Nq=32`、`C=150`、FP16、百万文档、64 KiB 逻辑读核对每文档 655,360 B、语料 655.36 GB、每查询有效输入 98,304,000 B、点积 3,145,728,000 FLOP、全 miss 逻辑请求 1,500 个、下发 21,680 B、返回 1,800 B。独立核算逻辑请求和有效字节，MQSim 的 NAND/PCIe 流量留给执行侧测量。
- **参数和边界**。用最小查询检查候选全覆盖、无重复、同种子复现、均匀与 Zipf 参数、跨模型预设、FP32、模板增量及尾部补齐。覆盖 `C=1`、`K=C`、`C=corpus_documents`、越界配置、容量超限和输出预算拒绝。缓存 0、可全驻留容量和有限 buffer 验证配置传递，动态命中率和反压留到运行时验收。
- **包和依赖**。对生成包运行通用结构校验。用独立元数据核对器从配置、候选和 IR 访问重新计算字节、FLOP、输出大小以及终态闭合。使用缺失候选分数依赖、越界切片、篡改 Work、错误输出大小的负例检查拒绝路径。核验报告声明其证据为合成负载结构和账本。
- **复现与完成条件**。在无需构建 SST/MQSim 的环境，从独立输出目录生成两次并比较候选、布局及 IR 包身份。README 给出生成、复检和扫描配置用法。保存命令、退出码、配置、断言及哈希。首批通过条件为可复现生成及结构、账本检查通过。

## 验收记录

- 生成器定向测试 10/10、通用采集 SDK 回归 16/16、Layout CTest 1/1 通过。主配置两次独立生成并复检，候选、布局及包文件逐字节一致，主配置字节、读请求和 FLOP 与账本预期一致。
- E0～E5 展开 115 个配置点。另生成千万文档语料的单查询元数据包，并生成每查询 24,000 个逻辑请求的 4 KiB 读粒度点。两点均通过包结构和独立账本校验。
- 10,000 查询主配置在默认 2 GiB IR 包预算下触发显式预检拒绝，估计需要 21,660,164,096 B。首批验收使用少量查询核对全尺寸语料元数据。
- 本机原始证据保存在 `results/maxsim/first-delivery.2FdWaQ/`，包含可复现命令、退出码、配置、断言和产物 SHA-256。证据范围为合成负载生成与校验。
