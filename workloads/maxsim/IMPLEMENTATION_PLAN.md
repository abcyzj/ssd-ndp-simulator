# MaxSim 实施计划

首批生成器、E0.1 本机配置和 E0.2 三条执行路径已交付，E0.3 本机定向验收通过（2026-11-19）。复现步骤见 [MaxSim README](README.md)。范围依据 [MaxSim 实验方案](../../docs/MaxSim_ndp.md) §2～§10 和 [V0.4.5 IR 契约](../../docs/contract-v0.4.5.md)。

## 首批生成器交付目标

在 `workloads/maxsim/` 提供独立的 Python 负载生成入口。输入一份实验配置，输出相同配置和种子下可复现的候选序列、逻辑布局、`ndpsim-static-ir/2` 包与核验报告。负载从查询向量及候选 ID 已就绪开始，到 Top-K 描述及完成令牌为止。仅生成形状、地址、Work 和依赖元数据。首批验收落在生成与校验，三条路径的 SSD 执行、硬件配置选型、并发调度与性能测量属于后续接入。

## 参数归属

| 文档参数 | 首批处理 |
| --- | --- |
| 模型、`D`、`Nd`、模板 token 增量、`Nq`、`C`、`K`、文档 FP16/FP32、查询分量字节数 | 固化 ColQwen3 主配置与 ColQwen2.5、ColPali 的成对维度和长度预设。展开形状、有效字节、点积 FLOP、输出大小。文档 `storage_dtype` 与分量字节数联动，查询类型独立。保留模型引用、可用 revision 和精排 HNSW 背景字段。 |
| 文档总数、均匀/Zipf、指数、查询内去重、候选顺序、热度置换、种子 | 生成候选和逻辑地址。分别使用 `layout_seed`、`candidate_seed`、`arrival_seed`，记录采样算法和版本。按 `p(r) ∝ r^-α` 顺序加权无放回，保持抽样顺序。同组实验复用候选和布局。 |
| 文档对齐、逻辑读粒度、排序选项 | 使用受支持的连续、4 KiB 对齐、不按 LBA 排序的语义，支持 4/16/64/128 KiB 粒度。生成有效切片与尾部补齐后的逻辑请求账本。 |
| `host`、`host_compute_free`、`device_all`，算力、固定开销、协议、带宽 | 一份 IR 供三个方案引用。保存各方案的声明、单位和参数来源，派生查询下发和结果返回的有效载荷字节。保存 MQSim XML 引用、哈希和后端身份字段，缺失时明确标记待提供。生成器现有带宽字段沿用首批命名，执行配置按下文 E0 的 PCIe 口径解释。100 GB/s 保留为解析参考。 |
| Host 缓存容量和 LRU、回填、预热、读窗口、全局 QD、暂存、批大小、重叠、引擎数 | 校验并保存为执行参数。IR 固定候选、读需求及数据依赖。实际命中、批次成员、反压和启动次数由后续执行时序决定。 |
| 开放泊松、封闭并发、查询数及 E0～E5 扫描 | 开放组用独立随机流产出到达时刻。封闭组保存并发度、候选顺序和完成后补发规则。提交主配置和分阶段扫描清单，以配置校验和派生量核验作为扫描交付。E6 可选扩展留到后续。 |

## 实施顺序

### 1. 配置与派生量

- 提供有效配置和参数来源，区分公开依据、仿真假设、继承项和派生值。区分实验建议测量查询数与本次生成的查询数，默认示例使用少量查询并保留主配置的语料逻辑规模。
- 对未知字段、未支持的模式、非法数值及字段组合失败关闭。检查 `1 ≤ K ≤ C ≤ corpus_documents`、形状和 dtype、对齐和 I/O 粒度、扫描阈值及 uint64 派生值。FP32 文档仍可配独立的 FP16 查询。
- 在编码之前报告候选条目、读切片、包、SQLite 临时索引和磁盘预算。用小规模生成量验证全尺寸配置。10,000 查询点如超过 SDK 部署预算，报告缺口并保留原配置和已有证据。

### 2. 候选和逻辑布局

- 冻结各随机流的种子和复现规则。为热度排名到文档 ID 生成固定置换。验证布局流、候选流、到达流互不消耗随机状态。开放到达序列保留整数 ns 转换规则与相同时刻的次序。
- 用一个只读语料逻辑对象表示文档槽位。`doc_bytes = Nd_effective × D × storage_component_bytes`，`stride = align_up(doc_bytes, 4096)`，偏移为 `doc_id × stride`。每个 IR 访问只覆盖有效字节。候选与读计划记录文档 ID、候选序号、原始访问切片和尾部补齐后的请求长度，填充只进入存储账本。
- 输出逻辑布局和最小 namespace 容量。提供了明确的页几何和容量时，可导出匹配对象目录的 `ndpsim-layout/1` 并检查范围与对齐。超出已给设备容量的配置保留派生容量报告，拒绝把地址取模或标成可运行布局。设备预装载状态由后续执行接入处理。

### 3. 算子声明与语义 IR

- 在负载目录维护版本化算子注册表和纯元数据大小规则。表达查询已就绪、候选的逻辑读取、逐文档 MaxSim、候选分数汇合与 Host Top-K 终态。每个文档评分依赖查询和该文档全部有效切片就绪，查询终态依赖所有候选分数。候选序号和稳定 stage key 用于核验提交顺序；只有真实语义依赖进入 DAG，避免为保持候选顺序把各文档评分串行化。
- 每个文档记录 `2 × Nq × Nd_effective × D` 点积 FLOP、有效输入和输出的 Work。MaxSim 输出为文档 ID 加分数，Top-K 输出含 `K` 条记录。保留逻辑访问到候选的关联供后续按文档重组批次。
- 复用 [`OperatorRegistry`、`PackageWriter` 和 `validate_package`](../../python/README.md)。可变输出大小使用负载内、绑定实现哈希的纯元数据规则，复检入口显式使用同一注册表。标记 `synthetic-fixture`、`split=fixture`，显式启用 fixture 校验。包内使用 SDK 四件套，其余产物放在包目录外。
- 单次生成产出展开配置、注册表、候选序列、布局及逻辑请求账本、IR 包、结构校验报告、独立账本核验报告和 E0～E5 扫描定义。记录生成器和仓库身份、种子、算法版本、输入和产物哈希。输出目录采用新路径，失败不得留下成功标记。

### 4. 首批验收

- **主配置账本**。以 `D=320`、`Nd=1024`、`Nq=32`、`C=150`、FP16、百万文档、64 KiB 逻辑读核对每文档 655,360 B、语料 655.36 GB、每查询有效输入 98,304,000 B、点积 3,145,728,000 FLOP、全 miss 逻辑请求 1,500 个、下发 21,680 B、返回 1,800 B。独立核算逻辑请求和有效字节，MQSim 的 NAND/PCIe 流量留给执行侧测量。
- **参数和边界**。用最小查询检查候选全覆盖、无重复、同种子复现、均匀与 Zipf 参数、跨模型预设、FP32、模板增量及尾部补齐。覆盖 `C=1`、`K=C`、`C=corpus_documents`、越界配置、容量超限和输出预算拒绝。缓存 0、可全驻留容量和有限 buffer 验证配置传递，动态命中率和反压留到运行时验收。
- **包和依赖**。对生成包运行通用结构校验。用独立元数据核对器从配置、候选和 IR 访问重新计算字节、FLOP、输出大小以及终态闭合。使用缺失候选分数依赖、越界切片、篡改 Work、错误输出大小的负例检查拒绝路径。核验报告声明其证据为合成负载结构和账本。
- **复现与完成条件**。在无需构建 SST/MQSim 的环境，从独立输出目录生成两次并比较候选、布局及 IR 包身份。README 给出生成、复检和扫描配置用法。保存命令、退出码、配置、断言及哈希。首批通过条件为可复现生成及结构、账本检查通过。

### E0.2 接通资源、数据路径和调度

1. **输入和预检。** 增加 MaxSim 的 SST 执行入口和可重放的 E0 运行配置。复用通用 IR/DAG、成本与资源接口、Layout、MQSim 和元数据消息。启动前复核包、注册表、结构与账本凭据、有效配置、XML 和后端身份，验证容量、读范围、资源配额和模型适用性。将预装载排空作为测量窗口起点。SST 负责模拟时间，MQSim 在 SST 时间边界内推进。
2. **实现三条路径。** `host` 经普通 NVMe 读，到 Host 的数据和完成事件均就绪后参与评分。`host_compute_free` 使用相同 Host I/O 和资源门控，评分和批启动服务为 0 ns，仍经过异步完成。`device_all` 计一次下沉命令开销，下发查询和候选 ID，经 MQSim 本地读、盘控暂存和评分，返回全部 ID+分数。三条路径共享 Host Top-K 阶段，终态等待全部分数在 Host 可见。
3. **保留请求粒度和反压。** 以生成器的逻辑读计划为依据保留 64 KiB 请求边界和候选顺序，由 MQSim 处理扇区与页的分解。复用 Layout 校验地址范围，避免沿用图搜索路径按页拆分后逐个串发的提交策略。全局 QD 统计已提交且未完成的逻辑读，完成后返还配额。每个文档首个读提交前检查文档窗口和输入暂存，最后一个读完成后释放窗口，评分完成后释放输入暂存。协议与结果缓冲另记实际占用。现有本地读接线若整批注入请求，需在入口拆出可受控的提交边界。
4. **按就绪状态组批并计费。** 文档所有请求及必要搬运就绪后进入评分队列。评分引擎空闲时立即从已就绪文档取最多 8 个，以候选序号作为同刻就绪的定序规则。每批按实际文档的 Work 求和，服务为 `batch_launch_ns + ceil(batch_flop / flop_per_ns)`。盘控暂存复用独立端口模型，E0 可沿用平台默认的 16 B/ns 并在有效配置中固化。统一将缺少已配置模型的 Host DRAM 及 Top-K 服务记作显式零开销假设。E0 继续用包含归约的等效评分模型。Cube 与 Vector 独立资源、tile 交接和重叠留作分项模型扩展。

NAND 介质读、FTL 和通道传输以 MQSim 模拟结果为准，盘控暂存搬运单独计费。E0 的两条 NAND 通道标称合计约 0.67 GB/s，适用于功能和账本验收。盘内读快于 PCIe 的情况需要另设硬件配置并实测模拟带宽，100 GB/s 保留为解析参考。

**E0.2 执行与 E0.3 本机验证记录（2026-11-19）**

- 三个 SST 进程消费同一 IR。各自在 40,000 页预装载排空后开始测量，完成 1,500 次 64 KiB 逻辑读、150 次评分、3,145,728,000 FLOP 和一份 120 B Top-K 描述。主点各路径均形成 150 个单文档批。慢算力、带尾部填充的夹具在 Host 和盘侧实际形成 1、7 两个批。免费路径的评分和批启动合计 0 ns。
- 两条 Host 路径各收到 98,304,000 B 文档数据。`device_all` 的文档 D2H 为 0 B，下发和返回有效负载分别为 21,680 B 与 1,800 B。各方向按 [E0 平台配置](e0-run.json) 加 32 B 应用头后，MQSim 观测到 26,472 B 和 2,252 B 链路字节，服务分别为 3,781 ns 和 321 ns。每条路径实测 NAND 读 98,305,536 B，含 1,536 B 映射读。盘侧文档暂存搬运 98,304,000 B。
- 分别以文档窗口 1、QD 2 和单文档暂存 655,360 B 触发对应反压。独立事件核对确认提交前持有配额、读完成后释放窗口和 QD、批完成后释放输入暂存，且所有路径恢复并排空。六个非法输入在测量前被拒绝。

### E0.4 交付记录中的百万文档扩展

- 保持模型形状和地址语义，生成 **655.36 GB** 逻辑语料及对应 Layout。在 7% OP 和现有二次幂几何规则下，百万 FP16 可以使用 **1 TiB raw** 档位。记录有效几何、逻辑容量及 Layout 末端，按新设备重新验证 NAND 路径和配置适用性。
- 在能够承载该规模的机器上预检内存、磁盘和耗时，运行入口显式传入适用的 `DeviceLimits`。16 KiB NAND 页下，1 TiB raw 设备的按页元数据估算项为 **16 GiB**，高于默认总预算 **4 GiB**。全量 Layout 需 **4000 万页**预装载，高于默认 **100 万页**。提高预算后仍需评估逐页初始化耗时。若改用加速初始化，须对照验证 FTL 初态、映射与后续读取行为。
- 大查询量执行前单独核验 IR、索引、trace 和输出预算。百万 FP32、千万 FP16 还需核查 MQSim 容量运算与现有几何上限。1000 文档页 E0 的通过证据覆盖本机正确性验收。

**E0.4 实现及本机验证记录（2026-11-19）**

- [百万配置](e0.4.json) 保留 E0 文档形状、槽位和放置，设备固定为 2 Channel × 1 Chip × 2 Die × 1 Plane，每 Plane 65,536 块、每块 256 页。共 67,108,864 个 16 KiB 页，raw 为 2,147,483,648 个 sector。各 Plane 扣除 7% OP 后将 sector 数向下取整，namespace 为 1,997,159,792 个 sector。Layout 覆盖半开区间 `[0, 1_280_000_000)`。单查询规模的 IR 与 SQLite 估算分别为 2,170,112 B 和 4,340,224 B。
- `--preflight-only` 走实际 SST 加载路径，核验设备 XML、Layout、包与读计划后，在设备分配前结束。完整 Layout 需 40,000,000 页，设备元数据估算为 18,257,870,848 B，其中按页项 16 GiB。默认元数据上限、默认预装载上限和过低的执行 RAM 预算分别被拒绝。
- 缩小夹具把每 Plane 块数降到 128，保留页和块内几何、通道拓扑及逐页预装载。三条放置均在 40,000 页预装载排空后完成查询，独立核对 NAND 地址和字节、PCIe 与评分账本。每条路径的 NAND 实测读字节为 98,305,536 B。夹具的单进程墙钟为 0.36～0.43 秒，含启动、预装载及查询。简单按页数放大 1,000 倍约为每放置 6～7 分钟，仅供估算试跑超时，全尺寸墙钟仍待目标机实测。
- 本机物理内存为 16 GiB，百万点的实际执行在设备分配前被 RAM 预检拒绝。1 TiB 点的实际分配、全量预装载和 NAND 测量待适用主机验证。`DeviceLimits` 和主机预算的传入方法见 [复现命令](README.md#e04-百万文档)。
